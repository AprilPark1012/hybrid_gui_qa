> 状态：**✅ 已实施（2026-09-17 补记）** —— D1~D4 全部落地：`pages` 声明（scenario/explorer 跨页探测与规划）、
> 原地断言 `after_step`（generator 渲染在第 N 步之后）、跨页同名消解（`搜索@列表页` / `搜索@详情页`，重名不再静默丢）、
> 换页证据闸（弱 url 断言红线，见 skill「换页证据质量闸」节）。
> 落地时的验收：`verify_cross_page.py` 三节判据 + 5 条负向全 FAILED · 全量 16 用例 PASSED。
> （原文「待AprilPark1012确认（2026-09-13 起草）」的状态行按实际执行结果更新。）
> 起因：已知边界里最扎眼的一条 —— "单目标页面（跨多页面不完整）"。目标是把「一条用例跨多个页面」变成一等公民。

## 一、现状：到底卡在哪（都带代码证据）

现在**每一环都假设"只有一个 URL"**，所以跨页不是"差个开关"，而是断在四个地方：

| 环节 | 现状 | 证据 |
|---|---|---|
| 场景声明 | 只有一个 `target.url` + `target.page`（页面说明） | `scenario.py` 的 `Scenario.url / .page` |
| 页面探测 | 只探一个 URL：`_collect_page_context(items, url)`；弹窗二次探测也只在这个页里 | `explorer.py:176` |
| AI 规划 | prompt 只喂一个页面的控件清单 + 一个 URL；`_finalize_map(url, …)` 只在开头补一个 goto | `explorer.py:246 / 360` |
| 定位映射 | `semantic_name → locator` 是**全局一张表**，重名直接 `continue` **静默丢弃**后者 | `generator.py:224 / 243` |
| 断言作用域 | 没有"这条断言属于哪一页"的概念（文本/计数断言天然是当前页） | `element_map.py` 断言只有 `expect_text` |

**顺带一个独立的真 bug**：`generator.py:224` 与 `:243` 遇到同名语义元素时静默跳过（`if name in out: continue`）——
单页时碰不到，一旦跨页（比如两个页面都有「搜索」按钮）就会**悄悄用错 locator**，症状是"定位到另一个页面的元素/找不到"，
而且没有任何告警。这个坑必须在 B 里一起修（改成显式冲突消解，见 D2）。

## 二、方案（4 个决策点，附推荐）

### D1 场景文件怎么声明多页 —— 推荐：`pages:` 列表，单页写法保留兼容
```yaml
# scenarios/contracts/contracts_cross_page.yml
pages:
  - name: 列表页
    url: http://localhost:8000/
    page: 合同列表：关键字搜索、客户/业务单元筛选、结果表格（编号可点击进详情）
  - name: 详情页
    url: http://localhost:8000/contract_detail.html?no=HT-1005
    page: 合同详情：显示编号/名称/管理单元/帐套/合同类型/客户/业务单元 + 返回按钮
scenario: |
  打开合同列表，按编号 1005 搜索，点结果行里的编号进入详情页，确认详情页字段与编号一致，
  点返回回到列表页，再用关键字 1005 搜索确认列表仍在。
```
· `target.url`（老写法）继续有效 = 单页场景；`pages:` 与 `target.url` **互斥**（同时给 → 报错 exit 2，不猜）。
· 每个 page 都给了**直连 URL** ⇒ AI 可以用 `goto` 切换，不依赖"能不能点到"。

### D2 跨页元素命名 —— 推荐：探测后做**全局唯一化**，冲突才加页名后缀
· probe 每页时给每个元素打 `page` 标记；合并时若同一 `semantic_name` 出现在多页 → 自动改名 `搜索@列表页` / `搜索@详情页`。
· 无冲突的名字**不变**（老用例零影响）。
· 清单里给 AI 看的就是最终名 ⇒ AI 只引用、不自造；generate 侧的 `loc_map` 从"静默跳过同名"改成**显式报错**（冲突无法消解就 `pytest.fail`，绝不悄悄用另一个页面的 locator）。
· 为什么不用 `页名::语义名` 两段式：落盘/校验/断言三处都要改，收益不如自动后缀直观。

### D3 AI 怎么跨页 —— 推荐：MVP 允许 goto 与点击导航两种，断言用刚做好的 `url` 类型兜住"确实换页了"
· MVP 不强制 AI 用哪种方式：每页控件都在清单里，AI 可以规划「点编号进详情」也可以「goto 详情页 URL」。
· **换页本身要有断言**（否则"点进去了吗"没验）：由场景 `assert_guard.must_contain` 要求断言里含详情页特征文本；
  手写用例可直接用 `{"kind": "url", "expect": "contract_detail"}`（V7.2 刚加的断言类型正好用上）。
· 二期（不在本次范围）：AI 自动推导航元素 + 自动补"页面已切换"断言。

### D4 资源与探测方式 —— 推荐：一个浏览器、一个 context、**顺序** goto 每页
· 本机 1.87G 无 swap，绝不为多页多开浏览器/并发探测；`_collect_page_context` 改造为"按 pages 顺序探，复用同一浏览器"。
· 单页场景探测行为与现在**完全一致**（不能因为 B 把老链路拖慢）。

## 四、验收标准（每条都要实测证据，不达标不放行）

1. **正向（真跨页）**：`cases/cross_page_detail.json` 实测 PASSED —— 列表页搜索 → 点编号进详情页（URL 变化 + 详情字段核验）→ 返回列表 → 再搜索确认。
2. **正向（AI 出题）**：`explore --ai --scenario-file scenarios/contracts/contracts_cross_page.yml` 产出用例，**跨页元素全部映射成功**（日志无 `⚠️ 仍未映射`），且该用例实测 PASSED。
3. **负向（防假绿）**：① 详情页断言值写错 → FAILED；② 断言"已到详情页"但没发生换页 → FAILED。
4. **冲突消解**：两页同名元素（如都叫「搜索」）→ 自动后缀 + 日志明示；人为构造无法消解的冲突 → `pytest.fail`（不许静默用错 locator）。
5. **回归**：现有 13 条用例全绿；`pytest tests/`（CLI 契约 + 断言契约）全绿；单页场景探测耗时与现状相当。
6. **红线**：`dmesg` OOM 不新增；`hermes-gateway-<profile>` NRestarts 保持 1；并发仍按内存降到 1。
7. **文档一致**：README / training.html（V7.3）/ SKILL / BACKLOG 与代码同步（旧表述绝迹、新表述就位）。

## 五、风险与不做

· **风险1 探测变慢/吃内存**：多页顺序探头，页数 ≥3 时考虑只探「当前步会到的页」；先按 ≤3 页做，超了给告警。
· **风险2 AI prompt 变长**（token 成本 ↑）：控件清单按页分组 + 每页上限（沿用现有 `items[:60]` 思路）。
· **风险3 老链路回归**：单页路径必须走原代码分支（不做"统一多页实现"的大重写），并由第 5 条验收兜住。
· **不做**：跨标签页/新窗口（`target=_blank`）流程；跨域登录态；AI 自动推导航元素（二期）。

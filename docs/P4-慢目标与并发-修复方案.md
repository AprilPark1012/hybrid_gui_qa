# P4 · 「慢目标 / 并发」下的假红 —— 根因与修复方案

> 状态：**方案待确认（未改任何代码）** ｜ 起草 2026-09-14 ｜ 触发：团队演示时同版本代码 `run all` 红 4 条、`--debug` 全绿
> 口径：先证据后结论；每条根因都有**本机可复现**的配方。

## 〇、TL;DR

- 两条根因，**都只在「慢 / 忙目标」下暴露**：R1 页面数据就绪无契约（主因）、R2 单一有状态 store + 每用例全局复位（并发叠加）。
- 本机复现（单进程、无并发、~30s）：`5 failed / 1 passed`；加一处「等页面就绪」后 **`6 passed`** ⇒ 根因与主修法均被实验证实。
- 最高优先级不是"补一处等待"，而是**把三件事产品化**：page-ready 契约（F1）· 定位判定改有界等待（F2）· 报错信息纠偏（F3）；再加**慢目标闸门**（F4）防复发。

## 二、根因（代码级定位）

### R1 · 页面数据就绪没有契约（主因）

`demo/contracts.html:166` `async function boot()` 先 `await fetch('/api/customers')`、`await fetch('/api/contracts')`，再 `renderCustomers()` / `render(CONTRACTS)`（`:176` `render()` 直接 `tb.innerHTML = ...` 覆盖，`:194` `renderCustomers()` 渲染客户弹层行）。
而测试脚本 `goto` 之后**立即**动作/断言（`framework/generator.py:198`、`:208` 内联 `page.goto(...)`，后面没有任何就绪等待）。慢目标下的三个后果：

1. **弹层行未渲染**：`点击 选择客户` → 立刻点 `pick-cN`，此时 `button[data-testid^='pick-']` 计数为 **0**
   → `scripts/conftest.py:427` 的瞬时 `cand.count()==0` 判定失败 → 走语义兜底 `_loc()`（`:367`）
   → 兜底是"现场探可见元素"，此刻一样看不到 → `:376` 抛 **`RuntimeError: 元素语义未找到: 选择@<客户名>`**（报错与该元素其实无关，属误导）。
2. **结果被晚到的首屏渲染覆盖**：早期动作在 `CONTRACTS=[]` 上做过滤，随后 `boot()` 的 `render(CONTRACTS)` 把 tbody **覆盖成全量 20 行**
   ⇒ `kind=count` 断言（期望 1/3/4）在 5s web-first 重试里只能看到 20 → 必红（实测 `5 × resolved to 0 elements / 9 × resolved to 20 elements`）。
3. **断言定位瞬时判定**：`scripts/conftest.py:500` `_resolve()` 同样用 `cand.count()` 瞬时值定生死，元素"晚到"就判失败
   → `:525` 抛 `断言 locator 失效且无语义兜底（该断言既没 selector 也没 element）` —— 而该断言**其实有 selector**，真因是"此刻为 0 个"（同属误导）。

### R2 · 单一有状态 store + 每用例全局复位（并发叠加）

`demo/app.py` 是进程内单一 store；生成的 conftest 每用例前 `POST /api/reset`（全局复位）。多 worker 并发时：

- 复位会把别的 worker **正在依赖的新建数据**抹掉；
- 任何 worker 的新建会把别人的**精确计数断言**顶掉。

本机已用"注入 3 条新建记录再跑"确定性复现：`cross_page_detail` 期望 20 实际 23、`search_customer_fuzzy` 期望 4 实际 6；复位后同批 4 passed。

### 为什么 `--debug` 会全绿 / 本机从没发现

- `--debug`：单浏览器 + 顺序 + **`--slowmo` 默认 200ms**（`framework/cli.py:488`）⇒ 把 R1 的时间窗整个拖过去；**不是"debug 下代码更对"**。
- 本机：`limits.safe_workers()` 恒为 1（1.87G 无 swap）⇒ **从未真正并发**；且本机目标快（`goto` 返回时数据已渲染，窗口 ~0ms）。两个盲区叠一起，掩盖了它。

## 四、改动清单（文件级 + 做法 + 风险 + 回滚）

### F1 · page-ready 契约（必做）

- **页面**：`demo/contracts.html` `boot()` 完成时设 `document.body.dataset.hybridReady = "1"`；`contract_detail.html` 同理（详情页也是异步取数）。
- **契约优先级**：`[data-hybrid-ready]`（显式契约，推荐）→ 退化方案：`.wait_for_selector(<可配选择器>)`，再退化到"关键列表行 ≥1"。
- **生成侧**：`framework/generator.py` 在**每个 goto 之后**插入 `_wait_ready(page)`（`:198` 场景首跳 + `:208` 每步 goto）；`scripts/conftest.py` 的模板新增 `_wait_ready(page)`（模板在 `framework/generator.py:543` `_CONFTEST_TEMPLATE`，改完**必须重跑 generate**）。
- **风险**：老页面没有 ready 标志 ⇒ 必须保证退化路径可用，且 `HYBRID_READY_TIMEOUT` 可调（默认 15s）。
- **回滚**：`HYBRID_WAIT_READY=0` 一键回到旧行为（生成物 + conftest 都读该开关）。

### F2 · 定位判定改「有界等待」（必做）

- `scripts/conftest.py:417` `_act()` 与 `:500` `_resolve()`：primary 不再用瞬时 `count()` 定生死；改为
  `cand.first.wait_for(state="attached", timeout=<可配>)` 后再 `count()` 判定；超时才降级语义兜底/自愈。
- 目的：元素"晚到"不再假红；同时**保留**"宁可报错也不点错"的语义（非唯一/多命中仍降级）。
- 风险：把"真缺失"从 0ms 失败变成等 N 秒失败 ⇒ 用 `HYBRID_LOCATE_TIMEOUT`（默认 5s）平衡；负向用例需复核（保证仍能快速 FAILED）。

### F3 · 报错信息纠偏（必做，成本极低、收益极高）

- `:376`：`元素语义未找到: X` ⇒ 改为先给**真实原因链**（"primary 定位到 0 个元素（等待 Ns 仍为 0）→ 语义兜底也未命中；
  若刚 goto，页面数据可能尚未就绪"）+ 建议（`--debug` 看逐步截图 / 检查 ready 契约）。
- `:525`：`断言 locator 失效且无语义兜底（该断言既没 selector 也没 element）` ⇒ 改为
  `断言主定位失效（等待 Ns 仍为 0 个）：X；该断言用的是 selector，没有语义兜底`（说人话，别自相矛盾）。
- 判据：**报错信息必须能直接指向下一步动作**，否则它本身就是一种"漂移"。

### F4 · 慢目标闸门（必做）

- 新增 `tests/verify_slow_target.py`：起 400ms 慢代理（进程内 `ThreadingHTTPServer`，不留常驻进程）→ 用**同一批 cases**跑关键 6 条 → 断言全绿 → 收尾复位。
- 前置改造（顺带产品能力）：让 conftest 支持 **`HYBRID_BASE_URL` 覆盖**（否则同一份用例无法指向代理端口，只能拷脚本改字符串）。
  ⇒ 好处：① 闸门可便宜实现；② "同一套用例跑不同环境（本地/代理/预发）"成为显式能力（团队会用）。
- 写进 `docs/BACKLOG-下一步优化.md` 复核清单 + skill 复核节。

### F5（可选）· 断言稳健化

把"列表恢复全量 20 行"这类**全量硬编码**断言换成与新增无关的断言（如"包含 HT-1001"/"行数 ≥ 20"），降低对数据基线的耦合。

### F6（R2 并发隔离，取决于档位选择）

- **F6a 每 worker 数据分区**（真并发）：demo 支持分区（`?w=<worker>` 或 cookie），`/api/reset` 只清自己那份；
  conftest 为每个 worker 的 context 注入分区标识；页面 JS 把它带进所有 `/api` 调用。用例断言不变。
- **F6b 保守降级**（保命兜底）：目标未声明"可并发"时并发降为 1，日志说明原因；要并发须显式 `--isolated-target`。
- 推荐 F6a + F6b 同做：默认安全，声明隔离后才放开真并发。

# P8 元素歧义闸门 —— 方案（批次 2 · 待确认后实施）

> 目标优先级裁决口径（沿用既定）：**② AI 语义准 ≈ ① 降人力 > ③ 稳定 > ④ 脚本健壮**；
> 同目标内 tie-break：**假绿风险 > 已知边界/功能缺失 > 新能力 > 机制自证 > 手工验证**。
> 本项服务 ②：AI/用例「看着对、其实点到另一个控件」就是典型假绿。

---

## 一、事故现象（批次 1 实测，3 条用例红）

给合同页搜索区加「...」弹层按钮时，它的 `title` 写成了与新建弹窗里那枚按钮**完全相同**的文案。
后果不是报错，而是**生成器把既有用例静默映射到了另一个控件**：

- 用例里写的是那枚弹层按钮的名字，生成的 locator 却指向**搜索区**按钮（被弹窗遮挡）；
- 运行期 `Locator.click` 等到 30s 超时 ⇒ 3 条用例红；
- demo 侧把搜索区按钮改名后红转绿 —— **但框架侧没修**：换个撞名就还会再犯。

## 二、代码级定位：四条静默路径

| # | 位置 | 行为 | 为什么危险 |
|---|---|---|---|
| **R1 根因** | `probe.probe_page` + `_assign_semantic_names`（同页唯一化） | 唯一化在**每一次 probe_page 调用内部**独立完成：`counts[base]==1` 就保持**裸名** | 同名控件**分属不同探测轮次**（基础页一轮、弹窗/弹层各一轮）时，每轮都只看到自己那一个 ⇒ **两个控件都拿到裸名**。谁拿到裸名，取决于**探测那一刻哪些控件可见**（弹窗没开 ⇒ 弹层里那枚根本不在本轮清单里） |
| **R2 合并** | `generator.generate_scripts` 现场补齐（`live[name] = …` 之后 `live.setdefault(...)` 合并弹层项） | 合并只按**字符串名**去重，**不是**按 base 名做冲突检测 | 基础页那枚的裸名先占位 ⇒ 用例引用裸名就落到它头上。**全程零告警** |
| **R3 留痕缺失** | `_assign_semantic_names` 内部 `it.pop("_base") / pop("_ctx")` | 唯一化**不留痕**：产物里只有最终 `semantic_name`，没有 `base_name` / 命名来源 / 冲突组 | 下游（generator、质量闸、用例作者）**无法区分**「这个名字本来就是唯一控件」还是「它只是那一刻唯一」。跨页唯一化 `uniquify_across_pages` 有写 `original_name`，同页这条没有 —— 两套口径不一致 |
| **R4 运行期模糊兜底** | `generator._CONFTEST_TEMPLATE` 里的 `_item_for()`（**唯一出处**；框架侧没有独立副本，改完必须重跑 `generate` 才进 `scripts/conftest.py`） | 逐字找不到时按**包含关系**随便挑：`if hint in k or k in hint: return v` → 实测 `_item_for("搜索")` 在清单 `[搜索@列表页, 搜索@订单系统, 重置]` 下**静默返回 `搜索@列表页`** | **无唯一性校验、无告警**，且 `dict` 遍历顺序即命中顺序 ⇒ 运行时静默点到「名字里含这个片段」的另一个控件。与「绝不返回可能点错的 locator」红线**直接冲突** |

补充：`_probe_declared_pages` 里的 `ambiguous` 判据（同名落到两个不同 locator ⇒ 显式失败）是**防御性**的，只在**跨页**路径可能被填；单页 + 弹层这条主路径上**没有等价检查**。

## 三、修法（三层，与既有闸门口径同源）

### L1 根治：**先合并、后命名** + 命名留痕

1. `probe` 增加一个「**在全量控件集合上统一命名**」的入口（现 `_assign_semantic_names` 直接暴露为可复用函数）：
   基础页控件 + 各弹窗/弹层控件 + 声明页控件，**合并成一个列表后只命名一次**。
   ⇒ 跨轮次同名会被同一个 `counts` 看见，两个控件**都**带 `base@上下文`（或 `base_序号`），**裸名不再被某一轮独占**。
2. 命名时留痕（新字段，向后兼容）：
   - `base_name`：唯一化前的基础名；
   - `name_source`：`exact` / `ctx`（上下文唯一化）/ `seq`（序号唯一化）/ `page`（跨页唯一化）；
   - `base_conflict`：该 base 名在本轮全量集合里出现的**控件序号列表**（≥2 即有过冲突）。
3. `uniquify_across_pages` 与同页唯一化**统一走同一条留痕逻辑**（消除两套口径）。

### L2 生成期：命中方式分级，歧义与模糊一律红线

`generate_scripts` 的 `loc_map` 从 `name → locator 字符串` 升级为带**命中方式**：

| 命中方式 | 判据 | 处理 |
|---|---|---|
| `exact` | 名字逐字命中，且 `base_conflict` 为空（该 base 在全量集合里唯一） | 通过 |
| `disambiguated` | 名字逐字命中，`name_source ∈ {ctx, seq, page}`（显式消歧，**本身合法**） | 通过 + **产物内注释标注**（`# 消歧名: base@上下文`）+ CLI 打印清单 |
| `ambiguous` | 名字逐字命中，但 `base_conflict` 非空（该 base 在当前页面存在 ≥2 个控件） | **红线**：`AmbiguousElementsError` ⇒ 不落任何产物、exit 2、给人话（列出候选与各自上下文，指路改成 `base@上下文` 或换 test-id 契约） |
| `fuzzy` | 靠包含关系/模糊对齐才命中（**逐字不存在**） | **红线**：同上（「猜一个可能点错的 locator」不允许出现在产物里） |

逃生口沿用既有惯例：`--allow-unmapped`（调试用）**不**绕过本闸门（它服务的是「探测不可用」的调试场景）；
如需临时放行单独给 `--allow-ambiguous`，产出物里写 `pytest.fail` 存根 + 注释，绝不静默放行。

### L3 运行期：模糊兜底从「静默」改为「有据可依或失败」

`_item_for()` 的模糊兜底改为：

1. 候选**唯一** ⇒ 接受，但打印/落日志：`⚠️ 模糊兜底命中：<hint> → <actual>（逐字名不存在）`；
2. 候选 **≥2** ⇒ 抛错并列出候选（含各自上下文与 test_id），提示怎么消歧；
3. `HYBRID_STRICT_LOCATE=1` ⇒ 完全禁用模糊兜底（CI 语义：失败即报，不猜）。

### 与之配套的质量闸 / 自测（测试的测试）

- `tests/test_element_ambiguity_gate.py`（**不启 Chromium**，纯函数级）：
  a. 合成「基础页 1 枚 + 弹层 1 枚同名」清单 ⇒ 断言**两枚都不裸名**、`base_conflict` 都非空（当前实现会红 = 复现 R1）；
  b. `exact` / `disambiguated` 两种命中**不误拦**（用现有用例库里的真名做样本，如 `搜索@列表页`、`选择@<客户名>`）；
  c. `ambiguous` / `fuzzy` 必须抛错且信息含候选；
  d. `_item_for` 多候选必须抛错（假 `playwright` 模块注入，不启浏览器）；
  e. 命名留痕字段存在且口径一致（同页/跨页同一套）。
- 端到端复现 runbook（需 demo，人工/脚本都可跑）：把合同页搜索区那枚按钮的 `title` **临时**改回撞名文案 ⇒
  - 旧行为：`generate` exit 0，用例被映射到搜索区按钮，3 条用例红（**复现**）；
  - 新行为：`generate` **exit 2** + 指名道姓（哪个用例、哪一步、候选有哪些）。
  跑完还原 demo（或用专门 fixture 页，别把撞名永久留在 demo 里）。
- 回归：`pytest tests/ -q`（当前基线 179 passed）· `cli all --workers 1`（17 passed / exit 0）· 未映射 0。

## 四、验收判据（先证伪，再下结论）

1. **能复现旧病**：临时撞名场景下，旧代码静默映射（3 条红），新代码 exit 2；
2. **不误伤**：既有 17 条用例（含 5 条 AI 产物用例里的 `@` 消歧名）新代码全绿，命名零变更；
3. **逃生口不偷偷放行**：`--allow-ambiguous` 之外的任何路径都不得产出带歧义的产物；
4. **运行期不再静默**：构造「逐字不存在、包含关系命中」的场景 ⇒ 唯一候选有告警留痕 / 多候选必失败。

## 五、迁移影响（必须提前说清）

- L1 会**改变部分既有名字**：以前「某一轮恰好唯一」而拿到裸名的控件，合并命名后会变成 `base@上下文`。
  ⇒ 引用裸名的手写用例会**未映射**，被既有映射质量闸拦下（**fail loud 是对的**），但需要一次**用例名同步**（同批次 1 那次改 3 个名字的做法）。
  ⇒ 实施时先出「受影响名单」，一条条列给人看，再动。
- L2 会让「逐字名不存在但能模糊命中」的历史用例**从绿变红**（这是本方案的**目的**，不是回归）。
- 不动的东西：Healer 的 Tier2 指纹/意图复验（那是**运行期容错**，已有 `score`/`gap`/唯一性判据，与本闸门不冲突）；demo 数据的随机性；AI 的自由选择权。

### S3 落地细节（2026-09-18）

改点：`generator._CONFTEST_TEMPLATE` 里的 `_item_for()`（**生成物的唯一出处**，框架侧无独立副本）
⇒ 抽出 `_fuzzy_lookup(hint)` + `_strict_locate()`，规则三条：

| 情形 | 行为 | 理由 |
|---|---|---|
| 逐字命中 | 不变（缓存 → 重探 → 命中） | 老路径零影响 |
| 逐字不存在、候选**唯一** | 接受 + `_log()` 留痕（`⚠️ 模糊兜底命中：请求名 → 实际名`） | 几乎不误伤，但「蒙」这件事必须留证据 |
| 逐字不存在、候选 **≥2** | **抛错**（列出候选名 + 各自 test_id/role + 三步改法） | 旧行为按 dict 顺序静默挑第一个 = 静默点错控件的入口 |
| `HYBRID_STRICT_LOCATE=1/true/yes/on` | 连唯一候选也不兜：**抛错并指名该开关** | CI 语义：失败即报，绝不猜 |

判据（都是真跑）：`tests/test_element_ambiguity_gate.py` **15 条**（新增 6 条测**渲染出来的生成物**——
模板渲染到临时文件 exec 后直接调它的 `_item_for()`，不启浏览器）；其中互锁判据要求
**模板与仓库生成物同时**具备 S3 接线、且旧的一行式静默挑法（`if k and (hint in k or k in hint):`）绝迹。
全量自测 **202 passed**；真实 `cli run --workers 1` **17 passed / exit 0**，
跑了本次运行日志：`模糊兜底命中` **0 处** ⇒ 既有用例全是逐字命中，S3 零误伤；dmesg OOM 无新增、网关未被动。

工作量估计：S1~S3 各自都是「小改动 + 中等验证」，合计约半天，可分两次交付（S1+S2 / S3+S4）。

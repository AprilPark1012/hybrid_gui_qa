## 一、本版主线

### 1. 框架确定性兜底补行定位（方案 ③）
- 新增**唯一入口** `element_map.apply_row_locator_fallback()`：只认一条能判死的规则
  **R1「刚新增的那一行」** —— 该步无任何行定位 + 前面存在「新增行」动作 + 自那次新增后
  **没有**任何步骤给出过行锚 ⇒ 补 `row_index: -1`（最后一行，引擎已支持）。
- **两处调用、一段判据**：explore 产出成型时补（`row_index` 直接落进用例 JSON，可审）+
  generate 渲染入口补（手搓用例与 AI 用例**共同的收口**）。
- **保守原则（宁漏不误伤）**：出现行锚后本批不再兜底；**只认精确键**（不走基名兜底）——
  实测「开票页的 `单位`/`数量`」会被订单详情页的同名重复控件带下水、补出错误的 `-1`。
- 字段口径收敛成一处：`ROW_LOCATOR_FIELDS` + `has_row_locator()`（判据与兜底共用）。
- 判据 6 条（含负向自证、跨页误伤负向样本、引擎 `-1` 支持）。

### 2. 现场探测补齐「场景已声明的约定」（真 bug 修复）
- **症状**（用户 2026-10-11 实测复现）：全新环境（没有 element_map 落盘）跑 `cli all --workers 2`
  -> `映射质量闸拦下：7 个语义名映射不上 -> 拒绝产出任何产物`。
- **根因**：场景里**已经声明**了 `probe_pre: [超, 切换为订单管理员]`，但 `generate` 的
  **两条现场探测路径都没应用它**（explore 侧 2026-10-10 就修了）⇒ 探测还是超管身份 ⇒
  详情页「编辑/新增行」置灰（只 force 点一下、不变状态）⇒ **编辑态控件根本没渲染** ⇒ 探不到。
  属铁律 13「同一能力多条实现路径要逐条对齐」的漏网。
- **修法**：两条路径探测前都走**同一个引擎** `run_pre_actions()` 应用 `probe_pre`
  （用例自带优先 → 其次按 `source_scenario` 回读场景 yml，与 `auth` 同优先级口径）；
  身份是**会话级** ⇒ 只跑一次（每页都跑会失败：切换后头像显示名已变，再按旧名找不到）。
- **效果**（同一条件实测）：缺失项 **7 → 1 → 0**；订单列表页探测覆盖 107 → **156** 个控件
  （含弹层 52 个）；`all` 由"拒绝产出"变成**能产出并跑完**（手搓用例 1 passed）。

### 3. 行内列控件（`_当前行`）收敛成唯一入口
- `_row_columns_to_items` 从 `explorer` 搬到 `framework/tools/probe/row_columns.py`：
  explore 与 generate 现场探测**共用同一份**。
- 为什么必须搬：generate **不能** import explorer —— explorer 依赖可选包 `browser-use`，
  会破坏「无 AI 依赖也能 generate / run」这条硬约束（`requirements.txt` 明写 browser-use 可选）。

### 4. 真 bug：模板渲染的调用没进 import 名单
- 方案 ③ 补出 `row_index=-1` 后渲染成 `_act_row(...)`，而 harness import 名单**漏了 `_act_row`**
  ⇒ **生成期闸门全绿、真跑 `NameError`**。已补 import，并新增通用判据
  `test_generated_case_scripts_import_every_harness_helper_they_call` 锁住
  「模板渲染出的调用 vs import 名单」成对维护（这类坑靠人眼守不住）。

## 二、「混合」口径正名（A+B）
- **培训页第 1 章原先**写「`Browser Use`（AI）」「Browser Use 负责思考，Playwright 负责执行」
  ⇒ 读者会以为框架用 browser-use 的 **Agent** 驱动浏览器。
- **事实**：全仓只 import `browser_use.llm`（LLM 客户端，如 `ChatDeepSeek`）做**直连结构化编排**，
  **从未 import 其 Agent**；`browser-use` 是**可选**依赖，`generate` / `run` 都不需要。
- 已改：培训页（首屏 / AI 侧标题 / 红框口径澄清 / 流程图 / [brain] 卡片）+ README（定位 + 口径澄清块 +
  能力对照表）；新增 **四段闭环证据表**（浏览器出证据 → LLM 出编排 → 确定性执行 → 浏览器裁决，
  每段标注「用不用 LLM / 代码位置 / 产物文件」）+「命令 → 职责 → 是否用 AI」对照表
  （明写 `cli all` **不含** explore；generate 缺定位是**现场探测补缺**，不是再叫一次 AI）。
- 判据 6 条并**同时盖培训页与 README**（一处加多处查），含负向自证与事实约束（全仓不得 import Agent）。

## 三、框架原则（本版新增 · 2026-10-11 定）
> **兜底有边界 · 约定优于兜底**：四段链路 explore(LLM) → probe → generate → run；
> explore 做不到的由框架在**后三段**兜底，但**只兜能判死的**（判不出来一律报红，绝不猜）；
> **该在 scenario 里说清楚的写进场景作为约定** —— 改场景比改框架成本低、更健壮、更通用；
> **兜底必须可审计**（补了什么 / 依据哪条规则 / 哪些没推定，全部打出来）。

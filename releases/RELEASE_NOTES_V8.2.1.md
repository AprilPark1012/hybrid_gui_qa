## 一句话

培训页新开一章 —— **《场景文件与用例文件：怎么手搓（两种业务场景）》**，
把「团队约定」写成可教学的一章：本框架支持的**两种业务场景**，对应**两种手搓文件**，
两条链路在 `cases/*.json` **汇合**。

## 一、为什么补这一章

框架支持两种业务场景，对应两种**要人写**的文件：

| | 场景① · 场景驱动 | 场景② · 用例驱动 |
|---|---|---|
| 你手搓的文件 | `scenarios/<模块>/<场景id>.yml`（自然语言） | `cases/<用例id>.json`（结构化步骤 + 断言）|
| 入口 | `cli explore --ai --scenario-file …` | `cli generate` + `run` |
| 产出 | `cases/ai_<场景id>_<HHMMSS>.json` | 直接进 `scripts/test_cases.py` |
| token | **花**（每次调 LLM；离线机器走录像回放） | **零**（纯确定性，可反复跑、可进 CI） |
| 适合 | 批量铺覆盖（一个场景 × N 组数据 = N 条用例） | 边界与负向、精确断言、把 AI 用例**固化**成回归资产 |

**汇合点 = `cases/*.json`** —— 这是两条链路**唯一的接口**，也是「AI 产的用例」和「你手搓的用例」
能跑同一条执行链、拿到同一份报告的原因。

之前这两处「怎么手搓、有什么约定」散在 `scenarios/README.md`、代码注释和老同事脑子里，
新人上手靠口传。这一章把它们收成一份可讲解、可照着做的材料。

## 二、新增章节内容（培训页第 4 章）

1. **两条链路对比** —— 花不花 token / 什么时候用哪个 / 推荐节奏（AI 产出满意 → 固化成手搓用例）
2. **场景文件** —— 完整字段表（谁读 / 干什么）· 一份字段注释完整的真实样例 ·
   四条写作要点（血泪教训）· 写场景前必知的 demo 三件事 · 五步操作流程
3. **用例文件** —— 五个顶层字段 · **7 个动作**（`goto/click/fill/select/check/press_enter/expect_text`）·
   **9 类断言**（`count/text/value/visible/hidden/enabled/disabled/checked/attr/url/first_row`）·
   一个真实用例模板 · 五步操作流程
4. **⚠️ 最关键的一处约定** —— `element`（语义名）到底是什么、从哪来：
   它不是 selector、也不是 `testid`，而是页面可被「读」到的身份，
   优先级 `placeholder` → `role+name` → 控件可见文本 → `title`/`aria-label`；
   **查法 = 先跑 `python -m framework.cli probe`，照 `output/element_maps/probe_*.json` 抄，别猜**
5. **六条团队约定** —— 只改源头不改产物 / 断言必须「操作前可确定」/ 不许跨用例依赖 /
   定位不唯一要如实报错（框架绝不按顺序猜）/ 元素口径对齐生产 / 交付前三条自检
6. **一页速查表** —— 「我想干什么 → 写哪个文件 → 跑什么命令」

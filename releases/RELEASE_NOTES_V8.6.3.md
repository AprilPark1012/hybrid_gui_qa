# V8.6.3 发行说明（2026-10-16）

> 上游路径：`releases/RELEASE_NOTES_V8.6.3.md`（交付时随代码包一并发出）

## 一句话

**以代码实现为基准的大扫除 —— 删掉 649 行失效物，并把两处「双实现」收敛成一个。**

V8.6 已经把**手搓链路整条删掉**了，但它删得不够彻底：留下了一批**残骸**。
残骸的坏处不是「占地方」，而是**看着还在用、实际永远走不到** ——
下一个人照着它办事就走进死路。所以本版按**「以代码实现为基准」逐处核对**，把它清干净。

## 缘起

一句话口径：**残留 = 失效物。**

V8.6（2026-10-13）把手搓链路（probe 驱动的确定性链路）整体删除、框架只剩**真 AI 链路一条**。
但那次是**按链路删**的，没有回头对**每一处还引用它的地方**：

- 有的**模块**再没人 import 了，可文件还在（`runner_unused.py`，149 行）；
- 有的**函数 / 符号**再没人调用了，可实现还在；
- 有的**判据**盯的机制已经被删，它**永远绿** —— 也就是**空转的假绿**（比没有判据更危险，它给假信心）；
- 有的**文档 / 文案 / 规格**还在教人走「两条链路」，还在报**过期的数字**。

判据很简单也很硬：**「以代码实现为基准」逐处核对** —— 实现不在、可它还被引用 / 还留在判据里，
那一处就是漂移源。本版就按这条清了两批（见下）。

## 怎么用

**对使用者：零影响、无需改配置。**

本版**没有新增能力、也没有行为变更** —— 删的是死物、收敛的是重复实现、改对的是文档与文案。
你照旧跑：

```bash
python -m framework.cli all --ai --scenario-file <场景.yml>   # 唯一链路，参数与上一版完全一致
```

> 唯一可能「看得到」的变化：培训页 `docs/training.html` 与 README 里那些
> **「两条链路 / 三种链路 / `cli probe`」的旧说法没了**，换成一条链路的说法；
> 子特性数从 50 改成 **54**（按代码真值）、判据数从 1123 改成 **1215**（当时真值）。

## ② 第二批：把「双实现」收敛成唯一权威 + 文档按真值改齐

### 收敛重复判定：自写启发式 -> 唯一权威

`explorer_explore` 里**自己再写了一份**「判断端点支不支持指名 `tool_choice`」的启发式。
而框架在 V8.6.1 就已经有**唯一权威**：

```
framework/shared/llm_compat.py::rejects_named_tool_choice
```

**为什么必须收敛**：同一件事**两份实现** = **一处改两处验** ——
改了一处、另一处**静默漂移**（不会报错、只是判断悄悄变了）。
现在 `explorer_explore` 直接复用权威函数，判定只有一份。

**并补 4 条判据**，含**负向自证**：把「自写 tool_choice 判定」这种坏输入喂给判据逻辑
**必须判红** —— 否则「收敛成唯一权威」只是口号，下次有人再抄一份没人拦。

## ③ 新增判据：思考档位口径一致

**`tests/特性10-CLI帮助契约/test_reasoning_effort_advice_consistency.py`（2 条）。**

**为什么加**：V8.6.2 刚把「思考档位」的坑写进多处（只认 `low`/`high`/`max`；
大 prompt 上用 `low` 会让模型**完全不返回 `tool_calls`**；本框架实测推荐 `high`），
可 `cli config` 的 `TUNABLE_CATALOG` 里**还留着旧口径「建议设 low」** ——
**同一个旋钮在两处给出相反建议**，用户照 CLI 做就会撞上结构化输出失效。

判据钉的就是这个：两处**口径必须一致**，并**负向自证**（喂一段旧口径文本必须判红）。

# V8.10.1 发行说明 · 身份前置的执行时机（不再押 AI 路线）

**日期**：2026-11-10　**类型**：缺陷修复（框架侧确定性缺陷 + 3 处可诊断性）

> 一句话：V8.10.0 在你机器上「重试 2 次才通过」，追下去不是 AI 抽风 ——
> **场景身份前置的执行时机错了**，同一份用例通过与否实际押在「AI 的路线是否恰好经过那一页」。

---

## 1. 现场：三轮三个不同的失败点

| 轮 | 结果 | 真原因 |
|---|---|---|
| 1 | generate 拒绝 | AI 有 2 步**没绑元素**（`click_new_tab` 查看订单、`click` 切换角色），且角色那步用了**纯基名**（跨页同名，框架唯一化成 `切换为发票管理员@订单列表页`）。**框架拦下是对的** |
| 2 | **126.5s FAILED** | AI 改走「等价直达 `order_new.html`」，第 11 步点保存 -> `#btn-o-submit` 是 `aria-disabled=true / perm-off`（当前身份无 `create_order`）-> 30s 超时；收尾闸 `RuntimeError: 身份前置整条用例都没能执行` |
| 3 | **391.2s PASSED** | AI 把首步改成 `goto orders.html`（注释还写着「角色切换入口「超」所在页」），身份建立成功 -> 通 |

**同一场景，三次不同的 AI 路线，结果从红到绿完全取决于路线** —— 这就是问题。

---

## 2. 根因（代码级，已复现）

`_harness.py` 的 `page` fixture 里放着「身份前置主路径」：

```
page fixture:  pg.goto(host) -> run_pre_actions(身份前置) -> yield pg    ← 在**用例体之前**
用例体:        _goto(login) -> _login_flow(...) -> ...                    ← 登录在这里，晚于上面
```

fixture 在**登录之前**执行，没有会话，身份菜单 `超` 解析不到 ⇒ **这段代码从来没真正生效过**。
真正起作用的只剩「每次导航后兜底 `_maybe_scene_pre`」⇒ 能否建立身份，取决于 AI 路线是否经过带身份菜单的页。

而 AI 选的 `order_new.html` 那条路上，该页**连头像节点都没有**（代码注释里早有这个实测）。

### 还揪出一个更隐蔽的：`probe_pre_host` 指错页，探针却照样绿

实测（同一台机器、同一个 demo）：

```
[合同列表页 http://localhost:8000/]  text=超 0 个   （等 1s / 3s / 6s / 10s 全是 0）
[订单列表页 http://localhost:8000/orders.html]  text=超 2 个
```

场景里写的是 `probe_pre_host: 合同列表页` —— **指错了页**。但探针期是「逐页尝试、能跑就跑」，
它在别的页把序列凑齐了 ⇒ **探针绿**，执行期严格按 host 页跑 ⇒ **必红**。
一个声明错误被探针的"宽容"掩盖了整整两个版本。

---

## 3. 本版改了什么

### 3.1 身份前置：唯一主路径挪到「登录之后」

```python
_ensure_scene_pre(page)   # 登录前导之后、用例体第一步之前（生成的用例里显式调用）
```

- 先 `goto(场景声明的 probe_pre_host)`，再用**同一引擎**跑前置；
- 建不起来**当场 `raise`**，文案直接给修法：
  「把场景的 `probe_pre_host` 改成**带业务导航**的那一页」；
- `page` fixture 里那段登录前的实现**已删除**（它从来没生效过）；
- 兜底路径 `_maybe_scene_pre` 保留（兼容独立用例），但不再是唯一指望。

### 3.2 探针期：先按声明的 host 页整组跑，跑不全就出声

```
[explore] [key] 场景探测前置已在声明的 host 页「订单列表页」上整组跑完：['超', '切换为订单管理员']
```

指错页时（实测形态）：

```
[explore] [!] 场景探测前置在**声明的 probe_pre_host**「X」上跑不全（完成 [] / 声明 [..]，缺 [..]）
        —— 多半是 `probe_pre_host` **指错了页**（这一页上没有这些控件）；
        探针随后会在别的页凑齐它，但**执行期只按声明的 host 页跑**，那条用例必红。
```

不硬红（宁漏不误伤），但**声明错误当场暴露**，不用等执行期红。

### 3.3 三个可诊断性修复

| 问题 | 改动 |
|---|---|
| 重试三轮用例**同名** `ai_*_125401.json` ⇒ 第 2 轮坏用例被第 3 轮覆盖，没法复盘 | 重试轮**换新 case_id**（仍是 `ai_<sid>_<HHMMSS>` 合法形态，清理判据不受影响） |
| L0 校验不合格**只打标题不打原因**，真原因要等重试用尽 | 当场打印本轮原因（有界 8 行） |
| generate 拒绝时**只回显一条** `[generate]` 开头的行（真原因不以它开头，被跳过） | 按内容关键字（质量警告 / 缺失项 / 没绑元素 …）**全量**回显，打印与喂回 AI 用同一份清单 |

### 3.4 老场景两处声明修正

- `pages` 去掉登录页（原「登录页说明」里的账号/角色口径挪到合同列表页，信息不丢）；
- `probe_pre_host`：合同列表页 -> **订单列表页**（实测身份入口只存在于后者）。

**L0 零重试、L1 零重试**（对比修复前：2 次重试、三轮）。

### 4.2 一类自测

**1653 passed / 3 skipped / 0 failed**（本版新增 7 条判据）

### 4.3 判据口径也跟着改了

原来有一条判据写死「`probe_pre_host` 必须等于**第一个业务页**」—— 等于把「指错页」固化成了契约。
现改为：**按声明的页名取 url + 不许落登录页 + 文件不存在给空串不抛**。

## 5. 升级须知

1. **场景若声明了 `probe_pre`，请确认 `probe_pre_host` 指向「真正带这些控件」的那一页** ——
   现在探针期会当场告警指出指错页（这是本次最有价值的护栏）；
2. `_ensure_scene_pre` 会让每条用例多一次导航（+1~2s），换来确定性；
3. 老场景/独立用例都不需要改代码；不声明 `probe_pre` 的场景完全零影响。

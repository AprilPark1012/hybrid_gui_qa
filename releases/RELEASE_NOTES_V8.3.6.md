# 发行说明 V8.3.6（2026-10-08）

> **主题：特性清单细化到子特性** —— 特性2 一分为二 + 全特性子特性化 + 「规格与用例」双向强校验
>
> 上一版：V8.3.5（2026-10-08）· 版本号单一来源：`build_tools/build_html.py` 顶部 `VERSION`

---

## 1. 起因

原先只有 9 个大特性，其中 **特性2「语义识别与分层定位」是个大混合物**：

| 特性 | 一类用例 | 说明 |
|---|---:|---|
| **特性2 语义识别与分层定位** | **95**（17 个文件）| 两个不同目标挤在一起 |
| 特性8 质量闸门体系 | 303（40 个文件）| 闸门集合，天然大 |
| 特性5 自愈闭环 Healer | **0** | 有实现、零判据 |

问题有两个：

1. **特性2 服务两个不同目标**：「语义识别」错了是 **AI 产出落不了地**；「分层定位」错了是
   **在生产系统上点错控件**。两者由不同代码层承担、失败模式完全不同，混在一起会互相绑架演进节奏。
2. **「哪条特性由哪些用例守着」只能靠人脑记** —— 加一条特性、忘挂用例，没人会发现。

### 2.3 关系从「靠人记」变成「机器守」

| 部件 | 作用 |
|---|---|
| `framework/tools/spec/feature_spec.py` | **单一来源**：10 特性 / 43 子特性 / 每个子特性挂哪些用例 |
| `build_tools/build_feature_map.py` | 生成 `docs/feature_map.md`（含统计口径）|
| `tests/特性9-质量闸门体系/test_feature_spec_contract.py` | **8 条判据双向校验** |

**8 条判据锁的东西**：

1. 规格里列的每个文件**必须真实存在**
2. 磁盘上每个 `test_*.py` / `verify_*.py` **必须有归属**
3. 特性编号**连续** 1..N
4. 子特性编号形如 `N.M`、同层唯一且连续
5. 每条子特性都要有 `name` + `goal`（防空壳）
6. 规格声明的目录必须存在；磁盘上的特性夹必须都在规格里（**防目录漂移**）
7. 生成的文档与规格**一致**
8. 规格覆盖的文件名集合与磁盘**完全相等**

### 2.4 顺手修掉一处**结构性隐患**

`test_test_layout_contract.py` 的 `in_feature_dir()` 里写死：

```python
any(parts[1].startswith(f"特性{i}-") for i in range(1, 10))   # 1~9，不认"特性10-"
```

⇒ 加第 10 个特性后**静默漏判**（特性10 的文件全被判成「散落」）。
**现在改为按规格的目录清单判定** —— 加特性不会再断。

## 5. 后续怎么加特性 / 子特性（你要的"可扩展"）

**只改一处** —— `framework/tools/spec/feature_spec.py`：

```python
dict(
    no=11, key="xxx", name="新特性名", goal="它解决什么问题",
    dir="特性11-新特性名",
    subs=[dict(no="11.1", name="子特性名", goal="目标",
               class1=["test_xxx.py"], class2=["verify_xxx.py"])],
),
```

然后：

```bash
.venv/bin/python build_tools/build_feature_map.py    # 重生成映射表
.venv/bin/python -m pytest tests/ -q                 # 判据会校验双向一致
```

**漏挂用例 / 目录名写错 / 编号重复 —— 判据会当场拦下。**

# V8.7.4 发行说明（2026-10-26）

> 承接 **V8.7.3**（同日）。本版只修一件事：**重试日志分不清「哪一档」也数不出「总共几次」**。
> 一句话结论：**不是计数算错，是两条日志长得一样。**

---

## 一、现场

GLM 跑 `all --ai`，日志里连续出现两条**一模一样**的语句：

```
[explore] -> 带着失败原因让 AI 重新生成（第 2/3 次尝试）
...
[explore] -> 带着**实跑失败原因**让 AI 重新生成（第 2/3 轮）
```

（第二条其实字面略不同，但「2/3」这个数字完全一样，看起来就是"重试两次但计数没递增"。）

用户判断「框架第一次重试和第二次重试打印的是同一条语句」—— 方向对，但真相比"计数坏了"更微妙。

---

## 二、根因：两档各有独立计数器，数字都对，但日志没有身份

重试有**两个层次**，各自维护自己的计数器：

| 档位 | 什么时候触发 | 计数器 | 上限 |
|---|---|---|---|
| **L0 产出物档** | 框架校验判定 AI 产出有结构性缺陷（不试跑，直接重生成） | `attempt` | `retry_limit`（默认 2 → 共 3 次） |
| **L1 实跑档** | 生成的用例**真跑起来失败**（断言是猜的 / 页面变了） | `l1_attempt` | 同上 |

两个计数器**各自从 0 起、各自 +1**，打印时都是 `attempt + 1` / `l1_attempt + 1`：

```
L0 第一次不合格 -> attempt 0→1 -> 打印 "2/3"      ← 本档第 2 次
L1 第一次失败   -> l1_attempt 0→1 -> 打印 "2/3"   ← 本档第 2 轮
```

**数字没算错**（各自确实是"本档第 2 次"）。错在：

1. **没有档位标识** —— 看日志不知道是哪一层在重试；
2. **没有累计计数** —— 数不出整轮到底重试了几次；
3. **两档共用"2/3"这个字面** —— 看起来就像同一个计数器没走。

这是**可观测性缺陷**，不是算术 bug。但它比算术 bug 更坑人：**数字对、结论错**，会让人误判成"重试逻辑坏了，所以 GLM 才一直失败"。

---

## 三、修复：每条重试日志必须给三样东西

```
[explore] [!] [L0 产出物档] 第 2/3 次产出**校验不合格**
[explore] -> [L0 产出物档] 带失败原因让 AI 重新生成（L0 第 2/3 次 · 累计第 1 次重试）
   ...
[explore] -> [L1 实跑档] 带**实跑失败原因**让 AI 重新生成（L1 第 2/3 轮 · 累计第 2 次重试）
```

| 要素 | 作用 |
|---|---|
| **`[L0 产出物档]` / `[L1 实跑档]`** | 一眼看出拦在哪一层 |
| **该档第 k/N** | 这一档还剩几次机会 |
| **累计第 M 次重试** | 新增 `retry_seq`，**跨档累加** —— 整轮重试了几次，直接数得出来 |

四处打印统一改：L0 校验不合格提示、L0 重生成提示、L1 重生成提示、L1 未通过提示。

## 四、判据（4 条，`tests/特性2-语义识别与步骤编排/test_ai_retry_contract.py`）

| 判据 | 守什么 |
|---|---|
| `test_retry_logs_carry_level_tags` | 两个档位标签必须都在 |
| `test_retry_logs_are_not_identical_text` | **两条日志文本必须不同**（本事故的最小复现形态） |
| `test_retry_logs_show_level_count_and_cumulative_total` | 每条都要有「该档 k/N」+「累计第 M 次」 |
| `test_retry_seq_is_shared_across_levels` | **AST 查** `retry_seq` 必须是跨档共享变量（定义早于首次自增、自增 ≥2 处） |

最后一条是关键：若有人把 `retry_seq` 改成各档自己的局部变量，**bug 会原样复活**，这条判据会当场红。

### 反向验证（证明判据不是假绿）

把 `framework/features/f10_cli/cli.py` 退回改动前 → **4 条判据全红**；恢复 → 全绿。

## 七、对「GLM 重试 3 遍都失败」的意义

有了累计计数，下次日志能直接回答"GLM 到底被要求重新生成了几次、每次原因变了没有"。

数量关系要知道：

```
L0 每档最多 3 次  ×  L1 最多 3 轮  =  最坏 9 次 LLM 调用
```

且 `_should_retry_again` 有一条**「失败原因与上一轮相同就停」**（省 token 不白问）。所以两种可能：

- **A**：GLM 每次犯**同样的**错 → 第一次重试后就被「同因不重试」掐断 → 你看到的"3 遍"其实是**你手动跑了 3 次命令**
- **B**：GLM 每次错得**不一样** → 真的重试到上限

新版日志能区分这两者。**请把新日志发我**，我按 `累计第 M 次重试` + 每次的失败原因变化来定位 GLM 到底卡在哪一步。

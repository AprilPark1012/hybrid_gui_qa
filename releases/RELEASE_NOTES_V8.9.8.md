# V8.9.8 发行说明

**日期**：2026-11-09
**主题**：场景说明补「**已带入 1 行，通常不需要新增行**」—— 省掉一轮 717 秒的白跑

---

## 一、这轮改的不是代码，是**场景说明**

真机跑 V8.9.7（2026-11-09）的结果：

| 轮次 | 结果 | 耗时 |
|---|---|---|
| 第 1 轮 | ❌ **FAILED** | **717.0s** |
| 第 2 轮（AI 带失败原因重新生成） | ✅ **PASSED** | 397.0s |

**链路的真实性没有问题**：`录像目录为空 → 实时调用并录制`，3 份录像（登录 + 第 1 轮 + 重试）。

## 二、第 1 轮为什么失败：**场景说明只说了「可以」，没说「不需要」**

开票页说明原文（`scenarios/orders/...yml`）：

```
发票行（可新增行）
```

AI 看到「可新增」，就选了这条路线：

```
点「新增行」→ 新行里填期次号/发票行类型/数量/单位 → 先点行保存 → 再点底部保存（两步）
```

**结果发票没有真的建出来** —— 搜索后第一行不存在，第 61 步断言抓到并如实报「表格没有第一行」。

第 2 轮 AI 自己改成：

```
不新增行，直接填「已带入的第 1 行」→ 只点底部保存（一步）  ->  PASSED
```

## 三、改法：把「必要性」写进说明

```yaml
      ⚠️ 从「去开票」进入时**已自动带入 1 行**（订单编号/合同编号已填好），
      **通常不需要点「新增行」** —— 直接填这一行的期次号/发票行类型/数量/单位，
      然后点底部「保存」即可。新增会多出一行空行，得单独填写、还得分两次保存
      （行保存 + 底部保存），容易漏。
```

**零代码**，只改场景 yml 的页面说明。

> 这类措辞以后每个场景都可能犯：**只说「可选」，不说「通常不需要」，AI 就会去试那条更复杂的路。**

## 四、顺带确认的两件事（这轮的正面证据）

### ① V8.9.6 的「断言失败给真值」**真机生效**

```
AssertionError: 表格没有第一行、或没有 'contractNo' 列 —— 无法验证「第一条记录」（断言无法成立）
    该页表格的实际列：['选择', '发票号', '发票类型', '发票日期', '业务单元',
                      '合同编号', '订单编号', '客户', '销售员', '币 种', '行数']
    提示：cell_field 要写 data-field（表头文案不算）；跨页断言必须用该页真实列
```

AI 第 2 轮的原话：

> 第 62 步：…（**用表头文案定位，避免 data-field 不一致**）

**它就是读了这个列清单才改对的。** 没有这行，下一轮还是盲改 —— 这正是 V8.9.6 那一半改动的目的。

### ② 行区信号（L37）依然良好

```
行定位缺失 0 处（步骤引用 36 个名字，其中撞上重复控件的 4 个；框架兜底补了 0 处）
```

**兜底 0 处** = AI 自己就写对了，不需要框架补。

## 五、⚠️ 这轮**没有**拿到的证据（如实说明）

V8.9.6 的**登录断言**在这轮没被验证：登录决策是 `登录步骤 4 步（AI 原始 4 步）`，
**AI 这次没写 `expect_url` / `expect_text`**。

所以「日志里不再出现『非操作动作，已跳过』」**不能**当作 V8.9.6 生效的证据 ——
只是这次 AI 压根没写断言。登录断言的实证仍以上一轮（V8.9.6 开发期）的
真机 `login_assert: expect_text 通过` 为准。

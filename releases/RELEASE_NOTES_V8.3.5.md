# 发行说明 V8.3.5（2026-10-08）

> **主题：用例看门狗默认超时 120s 上调为 600s** —— 正常的长用例不该被当成「挂死」切掉
>
> 上一版：V8.3.4（2026-10-07）· 版本号单一来源：`build_tools/build_html.py` 顶部 `VERSION`

---

## 1. 起因（用户本地实测）

V8.3.4 修好 `_auth.json` 之后，用户跑 `run --debug`：**手搓用例 PASSED**、**AI 全链路用例仍失败**。

失败形态很特别（日志最后三行）：

```
[TEST] click: 提交整个订单        <- 到这里就没了
[run] pytest 退出码 1
[run] [NG] 以 pytest 退出码 1 结束
```

**没有 FAILED 标记、没有 traceback、没有「元素找不到」** —— 就是**停在最后一个动作**。

对照：手搓用例结尾有明确的 `PASSED`。⇒ **这不是失败，是被掐死。**

---

## 2. 根因

| 事实 | 数值 |
|---|---|
| 该用例最后要等「订单已签收后**自动流转到已关闭**」 | demo 约定 **120 秒** |
| 整条用例实测耗时 | **165.79s**（本机验证）|
| `HYBRID_CASE_TIMEOUT` **默认值** | **120** ⇒ **必然撞死** |

**看门狗的用途是防「挂死」**（进程卡死、永远不返回），**不该把正常的长用例也切掉**。

而且它掐死时的**表现极具误导性**：无报错、无 FAILED、日志停在最后一个动作 ——
**看起来就像「用例在最后一步坏了」**，实际是超时。这个坑值得单独记一条排查心法（见 §4）。

---

## 3. 修法

**`HYBRID_CASE_TIMEOUT` 默认值：`120` → `600`**

- 定义在 `framework/tools/generate/generator.py`（生成期写入 `scripts/generated/_harness.py`）
- **已重跑 `generate --force`**，产物里的默认值同步为 600（只改源码不重生成 = 交付包里还是旧的）
- 口径注释与培训页参数表同步更新

**为什么不去教用户「设环境变量」**：

本地跑法有多种，环境变量的来源各不相同：

| 跑法 | 环境变量来源 | 终端里 `set` / `$env:` 有用吗 |
|---|---|---|
| 终端敲命令 | 该终端自己的 shell 环境 | 同一窗口内有用 |
| **PyCharm 点 Run 按钮** | **Run Configuration → Environment variables** | **完全无效**（另一个进程，不继承终端）|
| PyCharm 内置 Terminal | 那个终端的环境 | 同一窗口内有用 |

⇒ 让用户记这种东西，等于**把坑留给下一个人**。默认值合理才是根治。

---

## 4. 沉淀：一条排查心法（本次验证有效两次）

> **日志「停在最后一个动作、后续空白、无 traceback」⇒ 先怀疑超时/看门狗，而不是用例逻辑。**

对照特征：

| 形态 | 含义 |
|---|---|
| 明确的 `FAILED` + 调用栈 + 断言行 | **用例逻辑问题**（定位/断言/就绪）|
| 停在最后一个动作、无报错、无 FAILED | **被看门狗掐死（超时）** |
| 报「元素找不到」但 `page.url` 是登录页/空白页 | **前置没生效**（如登录前置），不是定位问题 |

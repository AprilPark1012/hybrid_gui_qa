# V8.4.5 发行说明（内部口径 · 2026-10-10）

> 主题：**「动作做了 != 生效了」+ 等待三要素 + 探测期上下文** —— 一串被埋了三层的静默缺陷链。
> 本版最大价值：**把"静默失败"变成"当场喊出来"**。

## 一、这版修的是什么（按被埋深度排序）

### 1. 动作后置校验（B）—— 本版最有价值的一块
**事故**：干净环境 E2E 卡在「等不到订单变『已关闭』」。我依次怀疑**等待时长**（30000→150000）、
**取数方式**（refresh=none→research），**两轮都没用**。最后翻磁盘状态文件才发现
**`fulfill` 表是空的 —— 订单从来没被提交过**。

**真因**：demo 详情页一行业务前置
`if (this.dirty) { status='页面有未保存的修改，请先点「保存」再提交'; return; }`
—— **不发请求、不报错，纯静默拒绝**；而 `_act` 只记「动作执行了」。

**新增能力**：业务动词点击后做**动作后置校验**
- R2 = 页面提示区出现拒绝语义文本（**原样回读**给人看，最强最直接）
- R1 = 无导航且无写请求
- 默认**只留痕**；`HYBRID_STRICT_EFFECT=1` 时**只让 R2** 判失败（R1 有误伤风险，宁漏不误伤）
- 框架**零业务词**：动词/拒绝词/提示区选择器全可配（5 个旋钮入 `cli config`）

**实证**（同一轮 verify 日志）：
```
[TEST] warn: [!] 动作后置校验：'提交' 之后页面**明确给出拒绝提示**
       -> '页面有未保存的修改，请先点「保存」再提交'（导航=无 写请求=无）
       => 该动作**很可能没有生效**，后面的断言会白给。
```
下游那行「等待超时 150000ms」仍在，但根因**在动作发生处**就被点明了 ——
以前要 8 分钟跑空 + 磁盘取证才定位得到。

### 2. 等待类断言的「三要素」（L27 + L27b）
等待类断言有**三个独立要素**，缺任一个都表现成"业务没流转"：
| 要素 | 修复 |
|---|---|
| **时长** | 由**场景声明的业务时长**驱动（新增 `declared_wait.py` 唯一解析入口）；AI 给偏小会**抬起并出声** |
| **取数方式** | 列表页不自刷新 ⇒ 无 selector 的等待默认 `refresh=research`（每轮重放搜索重取数） |
| **匹配口径** | 无 selector 时改为**逐个可见性判定**（隐藏 `<option>` 会让 `.first` 永久挡住） |

实测：AI 没给 → `timeout_ms=150000`（原 30000）；给 30s → 抬到 150000。

### 3. 场景依据补全（A）
yml 第 6 步写明：**每行填满 4 个必填 → 点行工具栏「保存」→ 再「提交」**，
并写明业务前提「有未保存修改时点提交不生效」。
实测：AI 新计划出现「点行工具栏保存，先保存订单行」+「提交」（此前是新增行后直接提交）。

### 4. 长文档硬编码用例名（顺手）
文档里写死了**带时间戳**的 AI 用例名（每次 AI 重跑必烂）⇒ 改 `<case_id>` 占位/稳定路径。

## 二、本版**已知未闭合**（如实交底，不做隐瞒）
1. **全链路 E2E 尚未跑通**。当前卡点：探测期**权限上下文**与执行期不同
   （场景里「切角色」是后面的一步，探测在之前跑）⇒ 「编辑」此时 `aria-disabled`，
   Playwright 常规点击被拒 ⇒ 编辑态/动态新增的控件采不到。
   **已定方向**（AprilPark1012拍定）：**删 `auth`、登录步骤化 + 探测前置统一**（见下节）。
2. 「AI 自造换页片段」已升级为**红线**（见三），但**登录步骤化落地前，AI 仍可能写出其它形态的错断言**。

## 三、本版新增的红线（质量闸）
**自造换页片段 → 红线**（从「只警告」升级）：
- 判据：片段与「声明页 URL + goto 目标」**一处都不匹配** ⇒ 断言**永远不可能通过**
- **误伤防护**：匹配集已从"声明页"放宽到"声明页 + goto 目标"；只在 goto 里出现 → 仍是警告
- 代价对照：不拦 = 白跑一整轮 E2E（约 8 分钟）+ 一轮 AI 重试才炸

# hybrid_gui_qa V8.2 升级说明（2026-09-22）

> 版本号单一来源：`build_tools/build_html.py` 顶部 `VERSION`/`CHANGELOG`。
> 本版是**口径版**：把「埋点只顶层有」从口头约定变成**可执行判据**，并按这个口径改造 demo、
> 补齐「**没有埋点也能定位**」的能力。

## 一句话

**只有顶层容器才允许埋点**（页面与弹层同一口径）；演示站点撤掉 **115 处**控件级埋点（只留 **27 个顶层容器**），
定位侧补齐**字段步 / `title` 消歧 / 元素身份**，让零 `testid` 下依然能**唯一定位并下钻**。

## 一、为什么（先看这条）

演示站点的埋点口径必须**和生产一致**，否则框架在真实页面上的可用性、正确性、健壮性都是空谈。
口径不一致时，框架应当**报错**，而不是假装通过。

于是本版做了两件事：
1. 把口径写成**硬判据**（规则 ⑤⑥）—— 交互控件无论层级一律不许有 `testid`；弹层内部（非容器本身）一律不许；
   **只有顶层容器**可保留埋点。
2. 把 demo 按这个口径**改到位**（撤 115 处），并补上「没有埋点怎么定位」的能力 ——
   否则判据会把框架自己逼进死角。

## 二、口径与判据（规则 ⑤⑥ · `tests/testid_policy.py`）

| 元素 | 允许 `testid`？ |
|---|---|
| 顶层容器（表格 / 弹层 / 分页器 / 状态区 …） | ✅ 允许（那是埋点的唯一落点） |
| 交互控件 `input/select/textarea/button/a/label/option` | ❌ **无论层级**一律不许 |
| 弹层**内部**元素（非容器本身） | ❌ 一律不许 |

**升级须知**：若你的页面里控件层仍带 `testid`，判据会**直接报违规** —— 这是**有意的**。

## 三、零 testid 下的定位（新增能力）

- **字段步**：工具栏「…」这类**无文本、无埋点**的入口，用「同容器内相邻字段（输入框/下拉）的语义」
  作为定位信号，并能**下钻**到目标控件；
- **`title` 消歧**：同名控件 / 裸图标按钮按 `title` 或**邻近文本**区分；
- **歧义如实失败**：命中多个时**报错并说明歧义**，禁止「按行序/顺序猜第一个」；
- **元素身份** = 容器锚点 + 相对路径 + `title`/邻近文本；
- 新增 `framework/tools/probe/semantic_locate.py`（语义定位，表达式一律是**字符串**而非 Locator repr）。

**怎么用**（一次真实验证，零 testid 页 + 弹层两条路径）：

```bash
python tests/verify_scope_locate.py     # 11 项：零 testid 下钻 + data-field 降级 + 歧义如实失败 + 容器消歧
python tests/verify_picker_layer.py     # 挑选层入口（含「探完弹层自己关掉」的兜底）
```

## 四、验证工程化（本版重点，全部是踩坑换来的）

- **单脚本预算 600s → 1200s**（`--timeout-s` 可调）：长用例此前是被预算**杀掉**的（exit 124），
  不是断言失败 —— 如实记 124，但别让预算假红；
- **`--jobs N` 并发**（默认 1 = 与改造前**完全一致**）。三条红线：
  ① 单脚本上限；② **浏览器脚本必须过内存闸**（≥550MB × 已跑浏览器数，**差一点绝不硬闯**）；
  ③ 会重写共享产物的脚本**独占**（它跑时谁也别起、它要起时等场上清空）；
- **产物质检**：`generate` 生成后**自洽闸**（引用了不存在的数据集 ⇒ 抛 `DanglingDatasetError`、
  **拒绝落盘**）+ **陈旧数据集自愈**；二类 runner **每个脚本之间**做产物质检 ⇒ 弄脏产物的脚本
  **当场点名**，不污染后续脚本；
- **每脚本完整日志落盘** `log/verify_logs/<脚本名>.log` ⇒ 红项可**自取证据**。

```bash
python tests/run_verifications.py --list                 # 条数以 --list 输出为准（不写死数字）
python tests/run_verifications.py                        # 串行（默认）
python tests/run_verifications.py --jobs 2 --timeout-s 1200
```

## 六、修掉的坑（都是自证出来的，记住它们比记住结论有用）

1. **产物「悬空引用」窗口**：验证脚本临时写用例、归档后**没复原产物** ⇒ `scripts/test_cases.py`
   留下**死引用** ⇒ 之后任何跑它的脚本都红，而且报 `FileNotFoundError` + pytest 退出码 **2**
   （= 执行环境问题）⇒ **看着像「环境/偶发」**（实测被误判成 flaky 绕了一圈）。
   现在四层设防：真凶自愈 + `generate` 自洽闸 + runner 脚本间质检 + 一类缺口判据。
2. **录像体检工具两个真 bug**：抠取正则非贪婪、遇场景内层引号提前截断 ⇒ 长场景**永远误报「没录像」**；
   覆盖判定严格相等 ⇒ 改「相等或完整包含」。
3. **负向判据「永远 SKIP」**：所有场景都有录像后，`e2e_scenario3` 的反例构造不出来 ⇒
   改成**自己造反例**（临时场景 + `try/finally` 零残渣），红线不再无人守。
4. **并发写竞争假红**：并行模式下 `generate` 与并发脚本撞 ⇒ 独占屏障修复。
5. **UTF-8 铁律违例**：新代码用 `text=True` 跟随 locale（Windows cp936 会炸）⇒ 显式 `encoding`。

## 七、兼容性与注意事项

- CLI 参数、用例格式、报告形态 **零变化**；不带新开关时行为同旧版（`--jobs 1` = 改造前一致）。
- 二类需要 **≥550MB MemAvailable** 才能起 Chromium，低于则**整套 SKIP（≠ 通过）**；
  差几 MB 时**别改闸门值硬闯** —— 要么腾内存，要么如实记 SKIP。
- 演示站点：`python demo/app.py`（默认 8000）。

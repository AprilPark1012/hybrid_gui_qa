# V8.9.0 发布说明

**发布日期**：2026-11-01
**主题**：补三块「旁路」能力 —— 看不见的控件要看得见、失败了要拿得出证据、定位不到时还有最后一手

---

## 一、这一版解决什么问题

V8.8.0 之后还剩三个缺口，它们有同一个特征：**主链路没问题，但边界场景没有兜底**。

1. **看不见的控件**：默认选择器只认 `button / input / select / textarea / a[href]` 加少量 `[role=...]`。
   老系统里大量可点元素是裸 `div[onclick]`、没有 `href` 的 `a`、`canvas` ——
   **无障碍树也看不见它们**（实测：非语义页 13 个可点元素里 5 个被降级成纯文本、1 个彻底消失）。
   结果是**静默错误**：AI 得出"这里没有可点的东西"，用例漏测，而整条链路全绿。
2. **失败没有证据**：失败时只有一段 AI 的文本理由，报给开发、报给客户都答不上"为什么失败"。
3. **定位不到就没了**：语义、a11y、可点击性都失败之后，框架手上再没有别的信息可用。

三块能力全部是**旁路**：主链路（`probe` / `generator` / `locator_bridge` / `run`）**一行没改**。

## 二、三块能力

### 1) 可点击性补探（`f03_locate/clickable_probe.py`）

按 **DOM 事实**判定，不猜：

| 信号 | 类别 | 口径 |
|---|---|---|
| `onclick` 属性 | 强 | 直接采信 |
| CDP `DOMDebugger.getEventListeners` 查到的 click 监听器 | 强 | 直接采信（`addEventListener` 在 DOM 里看不到） |
| `cursor:pointer` | 弱 | 需两条互相印证 |
| `tabindex >= 0` | 弱 | 同上 |
| `contenteditable` | 弱 | 同上 |

**为什么单条弱信号不放行**：现代页面几乎处处 `cursor:pointer`，放行它等于给每页加几十条假控件 ——
噪音会把真信号埋掉，等于没提示。

已接进 `scan_page`（新参数 `with_clickable`，`ScanResult.clickable_items` / `clickable_count`），
开关 `HYBRID_CLICKABLE_PROBE`（`cli config` 可见）。

**实测**：自建非语义页 6 个可点元素 —— 默认选择器只探到 1 个（原生 button），补探到 5 个
（裸 `div[onclick]` / 无 `href` 的 `a` / `cursor+tabindex` / `canvas` / `img`），
并**正确拒绝**只有 `cursor:pointer` 的那个。临时标记属性残留 0（框架开的自己关）。

### 2) CDP 失败取证（`shared/evidence.py`）

用 `context.new_cdp_session(page)` 抓 console / 异常 / network / 性能指标 / 无障碍树摘要 ——
**不需要为了拿 CDP 能力换掉 Playwright**。

三条硬规矩：

* **证据包不许成为泄密源**：网络头里的 `Authorization` / `Cookie` / `Set-Cookie` / `X-Api-Key` 等
  一律过 `redact_headers` 打码（证据包会被落盘、进交付件、被转发）；
* **非 Chromium 系降级不报错**：`supported=False` + 原因，绝不把用例搞挂，也绝不假装拿到了数据；
* **有界收集**：事件条数有上限，超了截断并留痕 `truncated=True`。

**实测**（真 Chromium）：console 4 条、network 11 条（含一个 404 且 `status=404`）、
性能 `Nodes=817` / `JSHeapUsedSize=4.6MB`、无障碍树 135 节点。

### 3) 视觉 grounding 兜底（`f03_locate/visual_grounding.py`）

确定性定位全失败时，最后还剩客观信息：**像素**。截图交给多模态模型要 **0-1000 归一化坐标**，
按截图实际尺寸换算成像素，点下去，**然后校验有没有生效**。

* 坐标换算 `x_px = round(x/1000*(width-1))`，越界夹紧；
* 回复解析宽容但不猜：抠不出两个数就返回 `None`（报 `parse-failed`）；
* 空回复做**一次收紧提示词重试**（国产模型思考模式会把 token 预算烧在 reasoning 上、
  `content` 返回空串且 HTTP 200 —— 静默失败）；
* 点完签名没变 => `no-effect`，**绝不报成功**；失败只报原因、不抛。
* 开关 `HYBRID_VISION_GROUNDING`（`cli config` 可见），模型走 `LLM_MODEL`。

**实测**（真调 GLM，1280×800 演示页，真值由 DOM `getBoundingClientRect` 给出）：

| 任务 | 模型输出 | 换算像素 | 偏差 | 结果 |
|---|---|---|---|---|
| 定位单个按钮 | (500, 351) | (640, 280) | **0.8 px** | 命中 |
| 4 个完全同名按钮中定位指定那一行 | (413, 659) | (528, 527) | **8.5 px** | 命中，点击后输入框被填入（生效） |

## 三、顺带修掉的两个框架自身 bug

1. **`run_acceptance._verdict()` 不认判定字符串**：`step_e2e` 里场景2 直接塞 `"ok_skipped"`，
   落到 `return "fail"` -> **E2E 那一步每次必红**，而它自己的子汇总写着「通过 3 · 跳过 0 · 失败 0」；
   更严重的是 **fail-fast 会连带跳过整段二类特性自测**（看着像跑过验收，最慢那段其实一次没跑）。
   修法：`_verdict` 幂等；+2 条判据 + 负向自证。
2. **判据文件缺 `tests/_runner` 的 sys.path**：单独跑必 `ModuleNotFoundError`，只在全量跑时被前面的
   模块"顺手救活"（隐式顺序依赖）。已补路径并写明原因。

## 五、诚实边界（不要当成已完成）

**取证与视觉兜底目前是「可调用、已实测」的能力，尚未在 `run` 的失败路径上自动触发。**
自动触发要改执行期契约（失败时抓证据 / 定位失败时兜底再试），属于独立变更，需单独评审。

**L22 仍未修**（慢目标下行区就绪信号缺失）：`verify_slow_target` 依旧是二类里唯一红灯，
修法方向是给「行区」补**可观测的就绪条件**（不是继续抬超时）。

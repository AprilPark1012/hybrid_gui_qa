# hybrid_gui_qa V7.8 · 数据参数化「真展开」（一组数据 = 一条用例）

> 版本日期：**2026-09-21** · 上一版 V7.7.1（2026-09-19）
> 交付形态：**代码包**（要那台连不上外网 LLM 的机器跑 AI 链路，再附 **LLM 录像包** —— 见 README「离线跑 AI 链路」节）

---

## 一、这一版解决什么

以前场景里的 `data:` 字段是**摆设**：框架只解析、不展开（跑起来会打一行「data 暂未展开，N 组数据被忽略」）。
一个场景只能跑一组数据 ⇒ 想多覆盖几组输入，就得**复制粘贴**出多条场景/用例，改一处忘一处。

本版把它**真的展开**：

- **一组数据 = 一条独立用例** → 报告里各占一行，失败能直接定位到**是哪组数据**出问题；
- 可以**只跑某一组**（`-k "<case_id> and <组名>"`），排障不用全量重跑；
- 写法沿用既有的占位符机制（`{datetime}` 那一套），写场景的人**不用学新东西**。

## 二、怎么写（照样板抄就行）

样板：`scenarios/contracts/contracts_search_by_no.yml`（3 组数据）

```yaml
scenario: |
  在合同列表页面的搜索框输入 '{关键词}'，点击搜索按钮，
  确认结果列表里出现编号为 {期望编号} 的合同记录。

# 一组数据 = 一条用例；id 可选（给了就进报告的用例名）
data:
  - {id: "编号-1005", 关键词: "1005", 期望编号: "HT-1005"}
  - {id: "编号-1007", 关键词: "1007", 期望编号: "HT-1007"}
  - {id: "编号-1020", 关键词: "1020", 期望编号: "HT-1020"}
```

对应用例（`cases/*.json`）里，把写死的值换成同名占位符即可：

```json
{"op": "fill", "desc": "在关键字搜索框输入 {关键词}", "element": "合同编号_名称_管理单元_合同类型_帐套", "value": "{关键词}"}
```

流程不变：改场景 → `explore --ai`（或用例手写）→ `generate` → `run`。

## 三、报告形态与「定位到哪组数据」

```
scripts/test_cases.py::test_ai_contracts_search_by_no_000813[编号-1005] PASSED
scripts/test_cases.py::test_ai_contracts_search_by_no_000813[编号-1007] PASSED
scripts/test_cases.py::test_ai_contracts_search_by_no_000813[编号-1020] PASSED
```

- 组名口径：优先用组里的 `id`；没写就取该组**第一个占位符的值**；再没有就用 `ds1/ds2…`。重名自动加序号。
- 中文参数名**不会被转义**（本版给 pytest 加了官方开关 —— 默认会把中文转成 `[\u7f16\u53f7-1005]`，
  那样「定位到数据集」就形同虚设）。
- 单组排障：`pytest scripts/test_cases.py -k "search_by_no and 编号-1007"`
  或走 CLI：`python -m framework.cli run --case <case_id>`（跑该用例的全部数据组）。

## 四、写错了会被拦（并告诉你差在哪）

数据组分两种写法错误，**都在 `generate` 阶段 exit 2 + 人话点名**：

| 错误 | 后果（为什么必须拦） |
|---|---|
| **少了**某个占位符的值 | 框架对未命中的占位符是**原样保留** ⇒ 会把 `{关键词}` 这个**字面值填进页面**，用例「看着在跑、其实全错」 |
| **多了**用不到的键（名字写错） | 写了不生效 = 静默误导，场景作者以为已经覆盖，实际没有任何作用 |

另外两种约定：

- **场景有 `data:` 但某条用例没用任何占位符** ⇒ 只**告警 + 不参数化**（不硬拦，避免误伤「一个场景 + 混合用例」的写法）；
- **场景把 `data:` 删了 / 用例删了** ⇒ `generate` 会**清扫过期的组数据文件**（否则用例会继续用上一版数据跑，
  属「改了没生效」的静默坑）。

## 五、框架内部改了什么（给维护者）

| 文件 | 改动 |
|---|---|
| `framework/scenario.py` | `data` 校验升级为严格形态（列表 / 每组映射 / 键是非空字符串 / `id` 非空且不重名）；删掉「一期不展开」警告 |
| `framework/generator.py` | 用 `case['scenario_id']` 反查场景取 `data:` → 落 `<cid>.sets.json` + 严格校验；带数据的用例渲染 `parametrize(indirect=True)`；`ctx` / `page` 两处 fixture 切掉参数后缀；清扫过期 sets |
| `framework/cli.py` | 新增 `DataSetsError` → `exit 2` + 人话（与映射质量闸同口径：**绝不落产物**） |
| 数据文件 | `scripts/datasets/<cid>.json`（基础数据）**格式不变**；多组另落 `<cid>.sets.json`（基础 ⊕ 组值） |
| `pyproject.toml` | pytest 关掉 id 转义 |

## 七、升级注意

- 本版**新增能力**，不改既有用例的生成与运行行为；直接替换代码包即可。
- 若你的场景已经写了 `data:`（此前只是被忽略）：升级后它会**真的展开**。先跑一次 `generate`：
  写对的直接生效；写错的会被拦下来并告诉你缺哪个占位符的值 —— 按提示把场景文案改成 `{占位符}` 写法即可。
- 需要多组数据但用例文案里没有占位符时，会看到一行告警（该用例不参数化），属预期。

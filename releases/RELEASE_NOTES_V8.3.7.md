# V8.3.7 发行说明

**版本**：V8.3.7
**日期**：2026-10-08
**类型**：🐞 缺陷修复（**严重**：干净环境下 `cli all` 一条产物都不出）+ ⚡ 性能治理
**上一版**：V8.3.6

---

## 一、这一版修的是什么

### 现象（用户内网 Windows 实测）

从 **V8.3.6 交付包**里起 demo、跑：

```
python -m framework.cli all --workers 2
```

**不产生任何产物**（包括 element map）。日志末尾：

```
[generate] [NG] 映射质量闸拦下：2 个语义名映射不上 -> 拒绝产出任何产物
[generate]    locator 来源：现场probe补齐 23/25 项，跨页 7 页；
              [!] 仍未映射 2 项: ['切换为发票管理员@订单列表页', '切换为订单管理员@合同列表页']
```

### 根因：**同一个能力在五条探测路径上不一致**

框架里「页面探测」原本**五份实现各自手写一遍步骤**，其中**两条漏了「可展开容器」**：

| # | 路径 | 文件 | 基础探测 | 可展开容器 | 弹窗/弹层 |
|---|---|---|---|---|---|
| 1 | 单页探测 | `explorer._collect_page_context` | ✅ | ✅ | ✅ |
| 2 | 跨页探测 | `explorer._collect_pages_context` | ✅ | ✅ | ✅ |
| 3 | **generate 现场探测** | **`generator._probe_declared_pages`** | ✅ | ❌ **漏了** | ✅ |
| 4 | **generate 单页惯例探测** | **`generator.generate_scripts`** | ✅ | ❌ **漏了** | ✅ |
| 5 | cli probe 阶段 | `cli.cmd_probe` | ✅ | ✅ | ✅（逻辑对，只是自己手写一遍）|

第 3 条漏掉「可展开容器」⇒ 拿不到右上角角色菜单里的「切换为XX管理员」；
第 4 条同样漏掉。第 5 条逻辑本正确，写它进清单只为**收敛一致性**。

**为什么在部分机器上「看不出来」**：`generate` 的 locator 来源是
「**element_map 快照优先，缺失项现场探测补齐**」。老机器上 `output/element_maps/` 里
恰好存着那两个名字，于是**命中快照、问题被掩盖**；交付包**不带 `output/`** ⇒
干净环境只能现场探测 ⇒ 缺陷暴露。

### 修法（用户选定的方案 B：统一入口）

新增唯一入口 `framework/tools/probe/page_scan.py::scan_page()`：

```
基础探测(probe_page) -> 可展开容器(expand_and_collect) -> 弹窗/弹层(_try_collect_modal_items) -> 合并(_merge_items)
```

**五条路径全部改调它**，各自只保留自己特有的部分（导航、登录、就绪等待、前置动作、DOM 上下文、行内列清单）。

**边界刻意划清**：
- 合并的是「**全页清单探测**」这 5 条链；
- 另有 **6 处单元素重探**（`healer` LLM 重猜 / `runner` 调试块 / `semantic_locate` 语义缓存 /
  `locator_bridge` Tier2 指纹 / `explorer._wait_fresh_items` / `generator._item_for`）**保持独立** ——
  它们不是全页探测，语义不同，强行合并反而错。归属已逐条核实并登记台账（L25）。

⇒ 以后新增一步探测动作（例如 iframe 内控件），**只改 `scan_page` 一处**，五条路径自动跟上。

## 二、性能治理（本版第二块）

### 为什么必须在本版做

统一入口把 `expand_and_collect` 带到了所有现场探测路径上，而它原来的等待循环**每轮都全页重扫**
（`probe_page` 对**每个元素**要打 ~13 次 CDP 往返）⇒ 实测二类验证
`verify_e2e_scenario2_handwritten.py` 从 ~59s 涨到 **866s**，导致二类全套 `timeout 1500` 被杀。

### 实测到的成本分布（七页现场探测，合计 260.9s）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| `goto` + 就绪等待 | 1.2s | 0% |
| `probe_page`（基础探测）| 101.3s | 39% |
| **`expand_and_collect`（可展开容器）** | **118.2s** | **45%**（最大单项）|
| `_try_collect_modal_items`（弹窗/弹层）| 40.3s | 15% |

**逐页看，发票列表页一个人吃掉一半**（因它有 212 个控件，代价被页面规模放大）：

| 页面 | probe | expand | modal |
|---|---|---|---|
| 合同列表页 | 13.4 | 15.9 | 12.0 |
| 订单列表页 | 17.7 | 19.3 | 13.7 |
| 订单详情页 | 4.7 | 9.6 | 8.0 |
| 开票页 | 2.2 | 5.3 | 2.8 |
| **发票列表页** | **60.3** | **68.1** | 3.7 |

### 做了三件事

**① 探测链收敛**（见第一节）—— 消除「多入口各写一遍」的隐患。

**② C：现场探测只探「缺口所属的页」**（`generator._pages_to_probe`，纯函数）

```
缺口 = 用例要的语义名 - 快照已覆盖的语义名
带页名后缀的缺口 `X@页名` -> 只探那一页
不带后缀的裸名 -> 才需要单页惯例探测
```

**③ D3：`expand` 重扫时只探新增元素**（`probe.visible_key_map` + `probe_page(only_indexes=...)`）

```
点开前先取一份「可见元素 key -> 索引」基线（**必须在 click 之前取**），
点开后再取一次，差集 = 真正新出现的元素 -> 只探这一小撮。
（原来是把整页 212 个元素重探一遍）
```

**⇒ 效果实测（七页现场探测）**：

| 阶段 | 改前 | 改后 | 变化 |
|---|---|---|---|
| `goto` + 就绪等待 | 1.2s | 1.4s | — |
| `probe_page`（基础探测）| 101.3s | 106.7s | 持平 |
| **`expand_and_collect`** | **118.2s** | **5.8s** | **↓ 95%** |
| `_try_collect_modal_items` | 40.3s | 46.9s | 持平 |
| **合计** | **260.9s** | **160.8s** | **↓ 38%** |

**整段 `_probe_declared_pages`：278.2s -> 159.9s。**

逐页看 `expand`（原先几乎等于「把整页重探一遍」）：

| 页面 | 改前 | 改后 |
|---|---|---|
| 合同列表页 | 14.8s | **1.2s** |
| 订单列表页 | 23.8s | **1.2s** |
| 订单详情页 | 6.6s | **0.9s** |
| 开票页 | 3.7s | **0.8s** |
| **发票列表页** | **65.4s** | **1.7s** |

**⇒ 省下的约 112 秒全部是「把整页重探一遍」的重复劳动。**
**剩余成本中心**是 `probe_page` 本身（106.7s，其中发票列表页 61.6s）——
它每元素要打 ~13 次 CDP 往返，属于 D1/D2 的范围（见第六节）。

**⚠️ 一个值得记下的排错教训**：D3 第一版把「点开前」的 key 基线**取在了 `click()` 之后**
⇒ 基线 = 点开后的集合 ⇒ 差集恒为空 ⇒ 循环一路 `continue` ⇒ 超时走兜底全探
⇒ **写出来的优化完全不生效，而判据全绿、日志无异常**。
最终靠**插桩探针**（记录 `visible_key_map` 每次返回值）才定位到。
⇒ 教训：**性能优化必须用「改前/改后实测数字」验收，判据绿不等于有效。**

### 方法学：**红态先行 + 负向自证**

三个方案**全部先写判据、拿红态、再实现**；每个判据都配**负向自证**（人为破坏 ⇒ 必须变红）：

| 人为破坏 | 结果 |
|---|---|
| 摘掉 `scan_page` 里的 expand 步骤 | **3 红** |
| 弹窗那步改回只吃 base | **1 红** |
| 去掉 D3 的 `only_indexes` | **红** |
| 恢复 | **全绿** |

## 五、影响面与风险

- **影响面**：`explorer` 两处 + `generator` 两处 + `cli` 一处 + 新增 2 模块。
  五处**行为等价或补齐**（缺的步骤补齐，其余步骤逐步一致）。
- **风险点**：探测面变大 ⇒ **首次探测耗时上升**（本版已用 C + D3 治理，实测见第二节）。
- **安全网**：映射质量闸**原样保留** —— 万一漏探导致语义名映射不上，仍然**拒绝产出**而不是产出假绿。

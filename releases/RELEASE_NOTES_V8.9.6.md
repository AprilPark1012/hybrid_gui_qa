# V8.9.6 发行说明

**日期**：2026-11-05
**主题**：**断言步骤可用性对齐** —— AI 能写的断言，框架都必须**真的执行**（L38）

---

## 一、问题：AI 写了断言，框架没跑

真机日志（V8.9.5，2026-11-05）原话：

```
[login] [!] 登录步骤里有非操作动作，已跳过：[(4, 'expect_url')]
```

AI 在登录决策里排了一步 `expect_url`（「断言已进入首页」），**执行器直接丢掉了**。
旧代码的理由写的是「执行器没有对应分支」，但这话只解释了现状，不是理由 ——
**断言只是校验、没有副作用**。丢掉的实际后果是：

> **登录成功的判定少了一道。** AI 想证明的事，一句空话。

## 二、三个改动

### ① 唯一断言执行入口 `_exec_assert()`

```python
_exec_assert(page, op, value, desc, **kw)     # 主链路与登录链路共用
  ├─ expect_url        → _assert_url
  ├─ expect_text       → _assert_text
  └─ expect_first_row  → _assert_first_row（缺 cell_field 直接报错，不猜）
```

- 登录段执行 `expect_url` / `expect_text`；失败**当场抛**，错误含「断言失败」+ 第几步哪个断言
- `expect_first_row` 在登录段仍不执行（要 `cell_field`，登录页一般没有表格行），但日志会**说清原因**
- **元判据**：`ASSERT_OPS` 每个成员都必须在 `_exec_assert` 里有映射 ——
  将来加断言类型时**不许只接主链路**

### ② 登录缓存的口径反过来：存决策，不存过滤结果

旧实现在落盘前就把不可执行步滤掉：`m.steps = steps` 然后 `to_json`。
后果很严重 —— **过滤规则一改，老缓存永远不生效**。L38 的断言就是这么被**永久埋在缓存里**的。

改成：

| | 旧 | 新 |
|---|---|---|
| 缓存里存什么 | 过滤后的可执行步 | **AI 的原始决策**（它本来就自称「决策档案，可审计」） |
| 过滤在哪做 | 写的时候 | **读的时候** |

好处：以后任何执行侧口径的改进，对**已有缓存**也立刻生效，不必逼用户删 `output/`。

日志也如实了：`登录步骤 5 步（AI 原始 5 步）` / `复用登录步骤缓存（可执行 5 步 / 档案 5 步）`。

### ③ `expect_first_row` 跨页取列：失败信息给**真值**

旧报错：

```
表格没有第一行、或没有 'orderName' 列 —— 无法验证「第一条记录」
```

排查只能重新猜「这页到底有哪些列」。现在：

```
表格没有第一行、或没有 'orderName_does_not_exist' 列 —— 无法验证「第一条记录」（断言无法成立）
    该页表格的实际列：['pick', 'contractNo', 'contractName', 'managementUnit',
                      'folder', 'contractType', 'customer', 'businessUnit']
    提示：cell_field 要写 data-field（表头文案不算）；跨页断言必须用该页真实列
```

> ⚠️ **修的过程中又踩到一个坑**：第一版用「单元格文本」兜底列名，
> 结果真页面（空表格，第一行是空状态提示）把 **「没有匹配的合同」报成了「该页实际列」** ——
> **这比不报更误导**。现在只认 `td[data-field]` 与 `thead th`，读不到就如实说读不到。

## 四、判据（17 条 + 3 组负向自证）

| 组 | 判据 |
|---|---|
| 元判据 | `ASSERT_OPS` 每个成员在 `_exec_assert` 有映射；未知断言动作必须报错（不许静默通过） |
| 派发 | 三个断言动作各自派发到正确实现；行断言缺 `cell_field` 明确报错 |
| 登录段 | 断言**真的被执行**；断言失败**当场抛**且错误能定位到第几步 |
| 生成侧 | 可执行断言不再被丢；`expect_first_row` 在登录段丢掉时**必须说明原因** |
| 缓存口径 | 不许把过滤后的步写回缓存；老缓存里带断言时读出来仍包含它 |
| 列名来源 | 优先 `data-field`；无 `data-field` 退回**表头文案**；**绝不用单元格文本**；都读不到返回空 |

负向自证（都按预期转红）：
1. 抹掉 `expect_url` 映射 → 元判据 + 派发判据红
2. 把过滤后的步写回缓存 → 缓存口径判据红
3. 列名用单元格文本兜底 → 列名来源判据红

## 六、教训

1. **「执行器没有分支」不是理由，是待办。** 只读的断言不执行，等于让 AI 的意图变成空话 ——
   而这类「写了不跑」比「跑错」更难发现，因为日志只有一行「已跳过」。
2. **缓存存决策、不存过滤结果。** 过滤规则会进化，把规则结果固化进缓存，等于把未来的改进全部作废。
3. **失败信息要给真值，不要给结论。** 同一件事：
   - 「没有这一列」→ 让人重新猜
   - 「没有这一列；这页有 A/B/C」→ 下一轮直接改对
   - 「这页有『没有匹配的合同』」→ **假真值，比不给还糟**

## 二、问题 1：行容器里的单实例控件

**日志证据**：

```
第 50 步  select → 期次号@开票页      ← 没给 row_index
实跑: RuntimeError: 定位失败：本页有 2 个同名匹配（期次号@开票页）
     请指明哪一行：row_index / row_text
```

**而生成阶段的提示只报了两个**：

```
· [行内控件缺行定位] 控件 '数量@开票页' 重复 3 个
· [行内控件缺行定位] 控件 '单位@开票页' 重复 3 个
```

**「期次号」一个字没提。**

**根因**：探测那一刻开票页只有 **1 行**，所以「期次号」`multi_match=1` → 不算重复控件 → 不提示 AI。而实跑到第 50 步时页面上已有 **2 行**。

**这是「探测时刻 ≠ 运行时刻」** —— 静态检测看不出会随行数增长的控件。

### 修法（方案 A，用户 2026-10-29 选定）

**同一容器里只要有一个控件 `multi_match>1`，这个容器就是「行容器」**（同一区域内每行/每条一份）—— 里面**所有**控件都可能随行数增长，哪怕当前只探测到 1 个，也要提醒 AI：

```
[explore] [key] 「期次号」（开票页）在**行容器**内（同区已有重复控件）-> 探测时只有 1 个，
                但运行时行数一变就会多匹配；**建议**给 row_index / row_text
```

**只提示、绝不改数据**：
- 不动 `multi_match`（改了会让质量闸误拦单行场景）
- 不替 AI 猜 `row_index`（猜错 = 写进别的行，静默污染数据）

**口径分级**：
- `multi_match>1` → 「**必须**给行定位」（探测时就确认重复）
- 行容器内的单实例 → 「**建议**给行定位」（探测时确实只有 1 个，但运行时可能变）

## 三、问题 2：跨页列清单不全（假阳性）

**日志证据**：

```
[explore] [!] 有 1 步 expect_first_row 要查的列不在本次探测到的列里:
    探测到的列: businessUnit、contractName、contractNo、contractType、customer、...
    - 第 63 步 要查列 '合同编号'
```

**你确认：发票列表页确实有「合同编号」列。**

**根因**：`_LAST_ROW_FIELDS` 只保留**最后一次**探测的页（订单列表页），而第 63 步在**发票列表页**。

**V8.7.15 当初的注释就写了「跨页场景下列清单可能对不上、仅供参考」** —— 现在把它从「预见到」变成「修掉」。

### 修法

新增 `_ALL_ROW_FIELDS`：**累积本次 explore 探测过的所有页**的列，供预检/反查使用。

| 变量 | 语义 | 谁在用 |
|---|---|---|
| `_LAST_ROW_FIELDS` | **最后一页**（每次探测清空重填）| `_fill_missing_row_column` 判勾选列唯一解 |
| `_ALL_ROW_FIELDS` | **所有页并集**（只累积）| 列名预检 + 表头反查 |

**为什么不合并成一个**：`_fill_missing_row_column` 依赖「最后一页」的语义判「勾选列是否唯一」—— 跨页并集里不同页的勾选列号可能不同，并集就不唯一了，那会让它放弃补全。

**清空时机**：`_ALL_ROW_FIELDS` 按**轮次**清（多轮重试不能串味），不按探测清。

## 六、还有一件事没解（要你知道）

**`RuntimeError` 里那句**：

> LLM 重猜为「未实现的预留路径（骨架）」：任何环境都不会启用，别按「配 key」排查

也就是说：**定位失败时的「自愈」目前是骨架，根本不会真的去重猜。** 这是刻意的 —— 你当时定的方案 A/B/C 里，B（运行时自愈自动重选）有「猜错就写进别的行、静默污染数据」的风险，**没选它**。

所以现在的策略是：**在生成阶段就把该给的行定位提示到位**（本版做的），而不是运行时猜。

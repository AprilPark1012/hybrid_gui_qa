框架必须做跨页唯一化（`HT_1001@合同列表页`），否则用例没法定位。

### 但它把真信息埋了

同一份日志里，真正要看的是这些：

- `登录前置：ok`（V8.7.25 修的那个）
- `同容器重复控件「用这个账号填入 →」`（V8.7.21 的行容器提示）

全被这 100 多行刷过去了。

**这和 V8.7.18 行容器 53 条、V8.7.21 是同一个道理** —— 这已经是第三次踩「提示变成噪音」这个坑。

各写一份必然漂移 —— 这正是 V8.7.26 的教训（改了一个漏了另一个）。

### 效果对照

**改前**（26 行）：

```
... HT_1001 出现在 4 个页 -> 已唯一化为 ...（2 行）
... HT_1002 出现在 4 个页 -> 已唯一化为 ...（2 行）
... × 13
```

**改后**（3 行）：

```

                   -> 已全部唯一化为 <名字>@<页名>，共 52 个（完整清单见 element_map 的 pages[].probe_items，日志不再逐条刷）
```

**26 行 → 3 行，压缩 88%。**

### 单个不合并

```
      [explore] [!] 跨页同名元素 '保存' 出现在 订单详情页、开票页 -> 已唯一化为 保存@订单详情页、保存@开票页
```

单个不是噪音，合并反而让人多绕一层。

### 合并不丢信息

合并后的汇总给出三件事：

1. **多少个**（13 个）
2. **范围**（HT_1001 ~ HT_1013）
3. **影响哪些页 + 唯一化总数**（4 个页、52 个）

完整清单指向 `element_map` 的 `pages[].probe_items` —— **信息在产物里，只是不在日志里刷**。

## 四、这次踩的坑

### 把 import 插进了 `try:` 块

我图省事用脚本在 `from framework.shared.llm_compat import ...` 前面插新 import，
但那行**在 try 块内部**（缩进 20 空格），插完直接把 `try/except` 结构破坏了：

```
SyntaxError: expected 'except' or 'finally' block
```

**教训：给模块加 import 必须挂在模块级 import 区**，不能"找第一个匹配的字符串就插"。
用脚本改 import 时，锚点要选**顶格的**那一处（`grep -n '^from framework'`）。

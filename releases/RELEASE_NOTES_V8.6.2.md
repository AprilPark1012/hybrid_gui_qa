# V8.6.2 发行说明（2026-10-16）

> 上游路径：`releases/RELEASE_NOTES_V8.6.2.md`（交付时随代码包一并发出）

## 一句话

**同一个框架，只换模型名 —— 四轮不过变成一次过。**

同一场景、同一判据、各跑一整轮真 AI 链路的实测：

| 跑的是谁 | 耗时 | 重试 | 结果 |
|---|---|---|---|
| 主链 **GLM `glm-5.3`** + `LLM_REASONING_EFFORT=high` | **18 分钟** | 零重试 | **一次通过** |
| 备用 **DeepSeek `deepseek-flash`** | 18~19 分钟 | 零重试 | **一次通过**（改造前：63 分钟 / 3 轮重试）|
| 同门 **GLM `glm-5.3-flash`** | —— | 四轮 | **全败** |

> **差异在模型档位，不在厂商。** 同一家的两个档位，一个一次过、一个四轮全败 ——
> 所以「这个模型行不行」只能靠**各跑一整轮真链路**回答，看名字、看文档、看同门兄弟都不算数。

除了这个结论，本版还有五件让链路更稳的事：**探索提示词瘦身 38%**、**弹层入口引导**、
**修一个跟页串页的 bug**、**业务等待白名单段压缩**、**质量警告回炉**。

## 缘起

V8.6.1 把「接第 N 家用哪个模型」这件事解决成了**只动三个环境变量**。
那之后的问题就变成：**换了模型，这条链路真的跑得过吗？**

于是拿同一个场景、同一套判据，各跑一整轮真 AI 链路去比。结果很反直觉：

- 主链 **GLM `glm-5.3` + `high`** 一次过；
- 备用 **DeepSeek `deepseek-flash`** 一次过（改造前是 63 分钟、3 轮重试）；
- 同门的 **`glm-5.3-flash`**（同一个厂商、名字只差一个 flash）**四轮全败**。

顺带在跑链路的过程中挖出并修掉了四类**「末梢报错、根因在上游」**的问题
（跟页串页的入口名、藏在弹层后面的控件、重复的 DOM 全量转储、
框架已知的质量警告没有回炉），见下。

## 怎么用

**跑链路的人只需要改 `.env` 两行**（其余全是框架内部行为，不用动配置）：

```bash
# .env —— 主链（实测一次通过）
LLM_MODEL=glm-5.3                 # GLM 端点 https://open.bigmodel.cn/api/paas/v4
LLM_REASONING_EFFORT=high
```

**换完模型先跑一次体检**（V8.6.1 起就有，换模型必跑）：

```bash
python -m framework.cli llm-doctor
```

> [!] **要用 GLM 就选旗舰 `glm-5.3`，别拿 `glm-5.3-flash` 当主链** ——
> 它为什么不达标写在「④ `glm-5.3-flash` 为什么不行」里。
> 同理，档位只从 `low` / `high` / `max` 里挑（见 ⑤）。

**提示词瘦身是自动的**，不需要任何配置 —— 它只是让框架发给 LLM 的东西更短、
同时把「清单里没有的事实」补齐。

## ① 探索提示词瘦身（C1）：删掉占 40.7% 的重复内容

**现象**：探索阶段发给 AI 的提示词里，有一份「额外 DOM 上下文」**全量转储**，
实测 **86,608 字符 = 整个提示词的 40.7%**。

**为什么能删**：这份转储里的元素，**语义清单里已经描述过一遍**。
同一份事实写两遍，AI 不会因此多知道什么，只是每次请求都多花 token
（探索阶段每一步都要调一次 LLM，等于每一步都在为重复内容付钱）。

**改法**：把**清单里没有的事实**并进清单条目，不再单独全量转储：

| 补充的事实 | 说明 |
|---|---|
| `visible:false` | 不可见 |
| `disabled` | 禁用 |
| `readonly` | 只读 |
| 非空 `test_id` | 有稳定测试 id |
| `idx` | 探针条目编号 |

口径：**只写非默认值** —— 默认靠「不写」隐含，提示词里写明这个口径。
（否则省下来的体积会被一堆默认值又填回去，白删。）

**元素对齐方式同时改掉**：DOM 记录与探针条目的**编号体系不同**，
按序号对齐在机理上就是错的（两套编号各说各话）；改为按 **稳定身份** 对齐 ——
**id / test_id / tag+可访问名**。

**实测**：提示词 **212,657 -> 130,289~132,260 字符（降约 38%）**。

## ② 弹层入口引导（C2'）：先开入口，再操作

**由来是一个实测死点**：点**未展开菜单**里的「切换为发票管理员」时 ——
locator **能 resolve**（元素确实在页面上），但报 `element is not visible`，
接着 click **30 秒超时**。

这类问题**靠「换个更好的定位写法」解决不了**：元素不是找不到，是**还没露出来**。

**改法**：

1. 探测期已经知道的「控件藏在哪个弹层入口后面」标成 `requires_open` 传给 AI；
2. 提示词新增**规则 1c**：**先 click 打开入口，再操作** ——
   把「弹层的存在」变成 AI 能照着执行的动作顺序（只告诉它「有这个入口」不够）。

## ③ 修 `requires_open` 跟页串页 bug

**现象**：`nu-avatar` 这类**全局导航控件**的 DOM id **每页都有**，
而原来的映射用一个 **单个 `element_id`** 做键 -> 后写的页把它**覆盖**掉 ->
**18 条、跨 5 页的条目全部塌缩成同一个错页码的名字**（AI 照着别页的名字去找本页的入口）。

**改法**：映射键改成 **(element_id, page)**，并**按条目自己那页优先解析**。

**真数据 before / after**：

| | 结果 |
|---|---|
| 旧 | **1 个错值**（被套到所有页上）|
| 新 | **5 页各取本页名** |

## ④ `glm-5.3-flash` 为什么不达标（如实记机理）

它在**行内操作**上写不对 -> 保存无效 -> 「提交」被**前端静默拒绝** ->
订单状态恒「已新建」-> 「等待自动关闭」断言**必然超时**。

> [!] **表象是判据超时**（很容易被误判成等待时长不够 / 框架的问题），
> **根因在模型写的行内操作**。这类「末梢报错、根因在上游」的形态，要顺着链路往回查，
> 别在末端加等待时间。

## ⑤ 体检 / 示例修正思考档位口径（C5）

两条**实测**出来的口径，文档里含糊写「low/medium/high/max」会把人直接带进坑：

| 坑 | 实测 |
|---|---|
| 档位取值 | `GLM-5.3` / `5.3-Flash` **只接受 `low` / `high` / `max`**；发 `medium` 直接 **`400`，`code=1210`** |
| 档位效果 | `low` 在 **8.9 万 token 的大 prompt 上会让模型完全不返回 `tool_calls`**（`finish_reason=stop`）|

所以：**主链配 `high`**，别用 `medium`（根本发不出去），也别在大 prompt 上用 `low`。

## ⑥ 质量警告回炉（C4）：框架知道了就得说

**现象**：框架自己已经识别的质量警告（**缺行定位 / 缺 element / 缺到达证据**）
原来**只打印、不参与重试** —— 后果是**同一个错被 AI 连着犯三轮**
（每轮都从零生成，框架明明知道哪里不对却不说）。

**改法**：把这些警告**拼进下一轮生成提示词**。口径三条（都为了不把「帮手」做成「干扰」）：

| 口径 | 为什么 |
|---|---|
| **只回炉不拦截** | 拦截是硬闸的职责，回炉只负责「说清楚」 |
| **已硬拦过的不重复说** | 同一件事说两遍，等于稀释提示词里的有效信息 |
| **没警告绝不凭空多出一段** | 宁可没有这一段，也不许凭空生成内容 |

## ⑦ 业务等待时长 / 页名白名单段压缩（C3）

**9,910 -> 1,500 字符以内**。

**白名单是权威口径、整段保留** —— 压掉的是重复啰嗦的说明文字，
不是口径本身（口径删了，判据就没有依据了）。

## ⑧ 新增工具：提示词体积度量

**`build_tools/measure_explore_prompt.py`** —— 探索提示词**体积度量**，
**纯函数、不起浏览器、不联网**。

**为什么单独做成工具**：本版的体积结论（40.7% / 降 38%）是**改造的判据来源**，
必须能**离线、可重复**地量出来 —— 「人工数一次、把数写进文档」的话，
下次改完没人能复查。

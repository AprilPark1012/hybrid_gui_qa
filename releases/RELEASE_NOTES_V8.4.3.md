# 发行说明 · V8.4.3

**版本**：V8.4.3 ｜ **日期**：2026-10-09
**主题**：**修「AI 勾选表格某一行」全链路的静默断点 —— 一处能力，从头贯到尾**

> 一句话：**V8.4.1 修的是「AI 产出里看着对、换环境就崩」的东西；V8.4.3 修的是「AI 明明写对了，却在链路上凭空消失」的那一类 —— 后者最难查，因为全程没有任何报错。**

---

## 起因：内网 Windows 第二轮实测

按「**模拟用户本地环境**」口径（起 demo → 删掉 `cases/ scripts/ output/` → 跑 `explore --ai`）实测，
在**干净环境**下 `explore --ai` 失败，报：

```
[!] 质量警告: 有 1 个操作步骤没有绑定元素（element 为空）→ 生成脚本定位不到，执行必然失败：check（勾选该订单行）
[NG] 校验不合格：AI 产出有结构性缺陷 -> 不试跑，直接带原因重生成
```

三轮重试，**每轮错法都不同**：

| 轮 | 现象 |
|---|---|
| 1 | `check` 步骤 element 留空（AI 知道要勾选，但不知控件名） |
| 2 | `expect_url orders.html` 失败（AI 漏了「点返回」那一步） |
| 3 | `Locator.check: Not a checkbox or radio button`（AI 把行里的 `HT-1001` 链接当成了勾选框） |

> 手搓用例里的正确写法是：`{"op":"check","desc":"选中该订单行","row_text":"全链路-{datetime}","cell_by":"index","cell_index":1}`
> —— **AI 三轮都没写出这一条**。

---

## 根因：一条能力要穿过 6 个关口，缺一处就"静默消失"

追这条链**用了 13 个提交**。每一层的症状都是「AI 不写 / 写错」，但断点各在不同层：

| # | 断点 | 症状 |
|---|---|---|
| 1 | AI 的产出 schema 里**没有** `cell_by` / `cell_index` | 它想写也写不出来 |
| 2 | 提示词没教「列没有 data-field 时怎么办」，且有一句会被泛化理解的禁止 | 它不知道走哪条路 |
| 3 | **探针只收 `td[data-field]` 的列** ⇒ 勾选列（无 data-field）根本不在清单里；且表头用 data-field 序号索引 ⇒ **表头错位** | 它拿到的依据本身就是错的，只能自造一个假列名 |
| 4 | 「JSON 步骤格式」示例只有 6 个键、还写着**「严格按此，不要多余字段」** | 字段名它从没见过 |
| 5 | 输出契约排在 prompt 的 **@37,900**，而 DOM 上下文占了 **71.3%** | 规则被自己的 prompt 淹没 |
| 6 | **`elementmap_to_case` 只透传 `row_text` / `cell_field`**；质量闸判定也只认 `cell_field` | **AI 写对了，落盘时被静默丢掉**，还被判「没绑元素」 |

**⇒ 第 6 层是真正的"最后一环"**：调试输出证实 AI 已经写出 `cell_by='index'`，但落盘用例里没有它 ——
产物的现象就是「只剩 `row_text`、闸门反复喊缺元素」。

---

## 修法（按链路的先后顺序）

**① 让 AI 表达得出来**
- 产出 schema 暴露 `cell_by`（列指定方式：`field` / `header` / `index`）与 `cell_index`（真实列号，从 1 起）
- 提示词补「无 data-field 的列 ⇒ `cell_by=index` + `cell_index`」，并把原句「不要用行内定位点选择按钮」**限定为只针对弹层里的选择按钮**（原措辞会被泛化，把主列表勾选框那条路也堵死）
- 「JSON 步骤格式」示例补上 `row_text` / `cell_field` / `cell_by` / `cell_index`，措辞从「不要多余字段」改为**「字段名严格按此，不要发明新字段名」**

**② 让 AI 的依据是对的**
- **探针按真实列位置遍历全部 `td`**（不再只挑 `td[data-field]`）：每列都给 `index`（真实列号）/ `field`（可空）/ `header`（按真实列号对齐）/ `kind`（无 field 时标注 checkbox/radio/action）
- 修掉**表头错位**（原来用 data-field 单元格序号索引表头）

**③ 让规则不被淹没**
- 输出契约提成模块常量，拼在 prompt **第 0 位**，并**同时挂到 system prompt**（长上下文里首尾双保险）
- 行内列清单从 `indent=1` 的 JSON 改成紧凑单行

**④ 给 AI「它已经会说的语言」**
- 无 data-field 的列**转成有名字的控件条目**（如 `选择订单_当前行`，前缀取该页已有行控件的公共前缀），**插到控件清单最前**（否则会被 `items[:60]` 截掉 = AI 根本看不到）
- 框架识别 `选择订单_<任意>` 这种引用 ⇒ 自动当作「选某一行」：后缀作为 `row_text`、列按 `cell_by=index` 补上

**⑤ 框架侧确定性兜底**（不依赖 AI）
- `row_text` 有、列缺失或**列名无效**（AI 会自造，如 `cell_field="pick"`）时，若探针清单里**所有**勾选列都在同一列号（= 唯一解）⇒ 自动补 `cell_by=index` + `cell_index`
- **多于一个候选就不补**，交给质量闸报出来让 AI 重生成（只补唯一解，绝不猜）；补了必出声

**⑥ 修好「落盘丢失」**（第 6 层断点）
- `elementmap_to_case` 增加 `cell_by` / `cell_index` 透传
- 「行内定位步骤不需要 element」的判定改为**两种列指定都认**（`cell_field` 与 `cell_by=index`+`cell_index`）

---

## 效果（本地实测）

**修复前**（每轮都有）：
```
[!] 质量警告: 有 1 个操作步骤没有绑定元素（element 为空）…：check（勾选该订单行）
```
**修复后**：该警告 **0 次**；落盘用例里 `check` 步骤为
```json
{"op": "check", "desc": "勾选该订单行", "row_text": "全链路-{datetime}",
 "cell_by": "index", "cell_index": 1}
```

**质量保障**：新增判据 27 条（特性 2/3/5/8），全部带**反向自证**（例如「只给 `row_text` 不给列**必须**仍报缺元素」，防止为了让判据变绿而放过真问题）；
一类全量 **847 passed / 2 skipped**（3 条既有失败：iframe 弹层能力缺失 ⇒ `probe_error` 未设，与本次无关）。

## 已知未修（本版范围之外）

`explore --ai` 在本 demo 上仍会因**下面两类 AI 产出质量问题**被质量闸拦下（闸门工作正常，是 AI 产出没达标）：

1. **AI 把表格行数据的具体值写死**（如 `?contract_no=HT-1001`）—— V8.4.1 已加闸门拦住，但 AI 尚未被引导改对
2. **AI 选错控件**（如把登录用户名「超」当角色菜单入口）—— 同上，语义校准判为严重误选并拦下

⇒ 这两类属于**提升 AI 产出质量**的范畴（提示词约束强度 / 重试反馈质量），列为下一版重点。

## 升级与验证

1. 覆盖到原项目目录（保持 `scenarios/`、`cases-data/` 不变）
2. 起 demo：`python demo/app.py`（或你原有的启动方式）
